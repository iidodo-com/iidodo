# docsearch — 過去の起案・資料のローカル全文検索

共有フォルダやローカルフォルダにある **Word（.docx）・Excel（.xlsx）・PowerPoint（.pptx）・PDF** の本文を、
キーワードで検索するツールです。「あの文書どこだっけ」「過去にどう書いたか」を調べるためのものです。

- **完全オフライン**: 外部API・ネットワーク通信を使いません。AI・埋め込みモデルも使いません（キーワード一致のみ）
- **読み取り専用**: 対象フォルダのファイルを変更・削除・移動・リネームしません（根拠は後述）
- **検索エンジン**: SQLite の FTS5（trigram）。日本語を分かち書きなしで部分一致検索します
- 使うライブラリ: Python 標準ライブラリ（sqlite3・tkinter・tomllib）＋ python-docx・python-pptx・openpyxl・pypdf のみ

> **重要（index.db の取扱い）**: インデックス（`index.db`）には、**対象文書の本文（正規化後のテキスト）が含まれます**。
> 元の文書と同等の機密情報として扱ってください。共有フォルダ・クラウド・メールに置かない／持ち出さない／不要になったら削除してください。
> 検索結果のCSVにも本文の一部（スニペット）が入ります。同様に扱ってください。

> **重要（スニペットの文字）**: スニペットは正規化後の文字で表示されるため（例：㈱→(株)、①→1、全角英数字→半角）、
> 引用する際は元ファイルで確認すること。

## 1. 環境構築

開発・テストを行った環境と、実際に使う環境が異なります。

| | 開発・テスト | 実際に使う環境（職場PC） |
|---|---|---|
| OS | Linux | Windows 11 |
| Python | 3.11.15（GUIのテストのみ 3.12.3） | 3.14.0 |
| SQLite | 3.45.1 | （Python 3.14 に同梱のもの。起動時に確認します） |

**開発・テストを行ったライブラリのバージョン**は `requirements.txt` に固定しています
（python-docx 1.2.0 / python-pptx 1.0.2 / openpyxl 3.1.5 / pypdf 6.19.0 / lxml 6.1.3 / pillow 12.3.0 ほか）。
**Python 3.14 での動作は未確認です。** 3.14 向けのメタデータ（対応バージョンの宣言）を持つのは、固定したライブラリのうち
pypdf・lxml・pillow・typing_extensions だけで、python-docx・python-pptx・openpyxl・et_xmlfile・xlsxwriter は 3.14 を宣言していません
（純Pythonのライブラリなので動く可能性は高いですが、確認していません）。

### 手順（Windows）
```bat
cd docsearch
py -3.14 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
```
- tkinter（GUI）は、python.org の標準インストーラなら同梱されています（「tcl/tk and IDLE」を外していないこと）。
- 起動時に SQLite のバージョンと FTS5・trigram を確認します。使えない場合は、日本語のメッセージで停止します
  （別の検索方式へは自動で切り替えません。メッセージの内容を作成者に伝えて、方針を相談してください）。
- 通信が必要なのは `pip install` のときだけです。ツールの実行中は通信しません。

### pip install が失敗したとき
失敗しうるのは、**バイナリ（C拡張）を含むライブラリ**です。

| ライブラリ | 理由 | 確認すること |
|---|---|---|
| **lxml**（python-docx・python-pptx が必要とする） | C拡張。対応する Python 版・OS 用の配布ファイル（wheel）が無いと、ソースからのビルドになり失敗する | 下記の共通の確認点。`pip install --only-binary=:all: lxml` で wheel だけを入れられるか試す |
| **pillow**（python-pptx が必要とする） | C拡張。同上 | 同上 |
| xlsxwriter・et_xmlfile・typing_extensions・python-docx・python-pptx・openpyxl・pypdf | 純Python（通常は失敗しにくい） | プロキシ・証明書・社内の PyPI ミラー設定 |

**失敗時の共通の確認点**
1. `python --version` が 3.14 か。`python -c "import struct; print(struct.calcsize('P')*8)"` が 64 か（32bit 版は wheel が無いことが多い）
2. エラーに「Microsoft Visual C++ 14.0 or greater is required」や「Failed building wheel」とあれば、wheel が見つからずビルドしようとしている。
   固定バージョンが 3.14 用の wheel を持たない可能性があるので、`pip install lxml pillow`（バージョン固定なし）を試し、入ったバージョンを控える
   （その場合はバージョンが開発時と違うため、テスト `python -m unittest discover -s tests -t .` を実行して確認する）
3. 「Could not find a version」「ProxyError」「SSL」なら、ネットワーク・プロキシ（`--proxy`）・社内証明書（`--cert`）・社内ミラー（`--index-url`）の問題
4. `pip` が古い場合は `python -m pip install --upgrade pip`
5. 職場PCで通信できない場合は、通信できるPCで wheel を集めて持ち込む:
   ```bat
   pip download -r requirements.txt -d wheels --only-binary=:all: --platform win_amd64 --python-version 3.14
   pip install --no-index --find-links wheels -r requirements.txt
   ```
6. `import docx` などが `ImportError` になる場合は、仮想環境を有効化しているか（`.venv\Scripts\activate`）を確認

## 2. 設定（config.toml）

`config.example.toml` を **`config.toml` という名前でコピー**し、`roots`（検索対象フォルダ）を実際のパスに書き換えます。
`config.toml` は `.gitignore` に入れてあり、リポジトリには含めません。

```toml
roots = ["D:/資料", "//サーバ名/共有名/過去の起案"]   # 「/」で書く。バックスラッシュなら '...'（シングルクォート）で囲む
db_path = "index.db"                                # 既定は、この設定ファイルのあるフォルダ（共有フォルダ上には作らない）
```
主な項目: `max_file_size_mb`（既定100）、`max_cells_per_xlsx`（既定50000）、`exclude_patterns`（既定 `~$*`・`*.tmp`・`Thumbs.db`）、
`open_mode`（`copy`＝読み取り専用の一時コピーを開く〈既定〉／`original`）、`snippet_chars`。全項目は `config.example.toml` にコメント付きで書いてあります。
設定の誤りは、キー名と原因が分かる日本語のメッセージで表示します。

## 3. 初回インデックス作成と更新

```bat
python index.py
```
- 初回も更新も同じコマンドです。**パス・サイズ・更新日時が前回と同じファイルは再処理しません**。削除されたファイルは、インデックスからも削除します。
- 進捗（処理済み／全体のファイル数、経過時間）を表示します。**Ctrl+C で中断しても**、完了したファイルは保存済みで、次回は処理済みの分を飛ばして再開します。
- 終了時に、**対象外（旧形式 .doc/.xls/.ppt、サイズ超過、リンク）・エラー（パスワード付き、AES暗号化、破損、読込エラー）・テキスト抽出不可（画像のみのPDF）**の件数と一覧を表示し、全件を `output/index_report_*.csv` に保存します。黙って飛ばすことはありません。
- 共有フォルダに接続できない場合は、何も削除せずに中止します。接続できているのに大量のファイルが消えたように見える場合（半数超）も、削除せずに止めます（`--allow-mass-delete` で解除）。
- 他のオプション: `--retry-errors`（前回エラーのファイルも再試行）、`--report`（走査せず一覧だけ表示）、`--check`（FTS索引の整合性確認）

## 4. 検索

### コマンドライン
```bat
python search.py "検索語" --ext docx,pptx --folder 契約書/2024 --since 2024-04-01 --limit 50
```
| 書き方 | 意味 |
|---|---|
| `契約 委託` | スペース区切り＝AND |
| `"有効期間は12か月"` | フレーズ（そのままの並びで一致） |
| `損害賠償 -上限` | 除外（`-` を語の先頭に付ける。除外語だけの検索はできません） |
| `--scope file`（既定）／`place` | AND を「ファイル内のどこかに」／「同じ場所（段落・セル・スライド・ページ）内に」で判定 |
| `--sort relevance`（既定）／`date` | 関連度（bm25）順／更新日の新しい順 |
| `--csv 結果.csv` | 結果をCSVに保存（UTF-8 BOM付き。Excelで開けます） |

- 全角・半角（ＡＢＣ/ABC、１２/12）、大文字・小文字は区別せず検索します。`* : ( ) "` などは、特別な意味を持たず、文字として検索します。
- 検索語が `-` で始まる場合は、`python search.py -- "-秘密"` のように `--` を付けてください。
- **3文字未満の検索語**（例：「納期」）は、trigram の索引が効かないため、LIKE による検索に切り替わり、
  「全件走査のため時間がかかる場合があります」と表示します（3文字以上の語と一緒に指定したときは、その語で絞り込んだ結果にだけ LIKE をかけるので、全件走査になりません）。
  この場合は bm25 が計算できないので、更新日の新しい順で表示します。
- 「ファイル内」のとき、並び順（関連度）はファイルごとの最良（最小）bm25 です。スニペットに出す場所は、検索語を最も多く含む場所
  （同数なら bm25 が良い場所、それも同じならファイル内で先頭の場所）で、「（ほかN箇所）」と該当場所の数も表示します。

### GUI
```bat
python gui.py
```
検索語の入力欄、拡張子・フォルダ・期間の絞り込み、並び順、「同じ場所内」のチェック、結果一覧（ファイル名・場所・更新日・スニペット）、
選択した結果の検索語を黄色で強調する詳細欄があります。**ダブルクリック（または「開く」）で、既定のアプリで開きます**。
「フォルダを開く」「パスをコピー」「CSV保存」のボタンもあります。GUIは、index.db と対象ファイルを読み取るだけで、変更しません。

**開く動作について**: 既定（`open_mode = "copy"`）では、OSの一時フォルダに**読み取り専用のコピー**を作って開きます。
元ファイルを直接開くと、Word・Excel が同じフォルダに `~$` のロックファイルを作ることがあるためです。
一時コピーは、GUIの終了時と次回起動時に削除します（アプリで開いたままで消せないものは残り、次回に削除されます）。
**コピーを編集して保存しても、元ファイルには反映されません。** 元ファイルを開きたい場合は `open_mode = "original"` にするか、「フォルダを開く」から開いてください。
一時コピーにも文書の本文が含まれるため、開いたあとは速やかに閉じてください。

### 場所の表記
| 形式 | 場所の例 |
|---|---|
| Word | `段落6`（本文直下の段落を、空の段落も含めて1から数える）、`表1 3行2列` |
| Excel | `予算!B7`（`シート名!セル番地`）。非表示シートも対象 |
| PowerPoint | `スライド2`、`スライド3(表)`、`スライド3(ノート)` |
| PDF | `p.3` |

## 5. 「読み取り専用であること」の根拠

1. **コード**: 対象フォルダのファイルを開くのは `core/pathutil.py` の `read_bytes()`（`open(..., "rb")`）だけです。読んだバイト列をメモリ上（BytesIO）でライブラリに渡すので、ライブラリがファイルに書き込む経路がありません。
   削除・移動・リネーム・属性変更の関数（`os.remove`、`shutil.move` など）は、一時コピーを扱う `core/opener.py` 以外には書いていません（`tests/test_static.py` で検査）。
2. **DB**: 検索側は index.db を読み取り専用（`mode=ro`）で開きます。index.db は対象フォルダとは別の場所（既定は実行フォルダ）に作ります。
3. **開く操作**: 既定は一時コピーを開きます（上記）。
4. **テスト**: インデックス作成（初回・差分・再試行）、検索、CSV保存、開く操作の前後で、対象フォルダの一覧・サイズ・更新日時（フォルダ自体の更新日時も含む）が変わらないこと、
   対象フォルダ内のファイルを書き込みモードで開いていないことを確認しています（`tests/test_incremental.py` の `ReadOnlyTest`）。
5. **この保証の限界**: OS が管理する「最終アクセス日時」は、読み取りで更新されることがあります（本ツールでは制御できません）。
   最も強い保証が必要な場合は、読み取り専用の権限（共有フォルダの読み取り専用アカウントなど）で実行してください。`open_mode = "original"` では、Word・Excel がロックファイルを作ることがあります。

## 6. index.db の取扱い注意

- **文書の本文（正規化後のテキスト）を含みます**。元の文書と同等に扱ってください（持ち出し・共有・メール添付・クラウド保存をしない）。
- スニペット表示のために場所ごとの本文を保存するので、検索に必要な範囲を超えて「元ファイルの複製」を作ることはありませんが、
  本文が復元できる形で入っていると考えてください（trigram の索引だけからでも、内容はかなり推測できます）。書式・画像・メタデータは保存しません。
- 保存場所は `config.toml` の `db_path` で指定します（既定は実行フォルダ内。共有フォルダ上には作らないでください）。
- 容量は、本文の約7倍が目安です（ダミー文書での実測。`verify.py --bulk` で測れます）。
- 不要になったら、`index.db` と `output/` 内のCSVを削除してください。

## 7. 既知の限界

- **本文のみが検索対象**です。ファイル名・フォルダ名では検索できません（`--folder` はフォルダの絞り込みにだけ使えます）。
- **OCRはしません**。画像のみのPDF・ページは「テキスト抽出不可」として一覧に出します。図や画像の中の文字は検索できません。
- **旧形式（.doc/.xls/.ppt）は読めません**（対象外として一覧に出します）。
- **パスワード付き**: Office は、暗号化されたOLE形式かどうかの署名で「パスワード付きの可能性」と判定します（旧形式との厳密な区別はしません）。
  PDF は、パスワード付きと、**AES暗号化（pypdf が追加ライブラリ cryptography を必要とするため読めない）**を区別して一覧に出します。
  AES暗号化のPDFは実務では珍しくないため、件数をインデックス作成後の一覧で確認してください。
- 取り出せない内容: Word のヘッダー・フッター・テキストボックス・脚注、PowerPoint のグラフ・SmartArt・マスターの文字、Excel の図形内テキスト・コメント、Excel の数値セル（設定で数値も取り込めます）。
- Excel の数式セルは、保存されている計算結果（キャッシュ値）を対象にします。キャッシュが無いセルは一覧（数式キャッシュなし）に出します。
  セル数が多いファイルは `max_cells_per_xlsx` で打ち切ります（走査セル数の上限は、その10倍）。
- **PDF の日本語抽出の品質**は、PDFの作り方に依存します（文字間に空白が入る・縦書き・段組で順序が乱れる、など）。
  本ツールの検証はダミーPDFで行っており、**実際のPDFでの抽出品質は未確認**です。
- 3文字未満の検索語は LIKE（全件走査）になり、bm25 による関連度順は使えません。
- 内容が変わっても、パス・サイズ・更新日時がすべて同じファイルは、変更として検出できません。ファイルのリネームは、削除＋新規として扱います。
- index.py を同時に2つ実行したり、インデックス作成中に検索したりすると、ロックで待たされる・失敗することがあります。
- 動作確認の範囲: 開発環境（Linux、Python 3.11／GUIは3.12）。**Windows 11、Python 3.14、UNCパス、260文字超のパスの実動作、数万ファイル規模、職場PCでの実動作は未確認**です。

## 8. テストと検証

```bat
python -m unittest discover -s tests -t .      # 自動テスト（GUIのテストは、画面を開けない環境では自動的にスキップされます）
python verify.py --work verify_out --bulk 400   # 期待値との突き合わせ（見逃し・誤検出の集計）と、速度・サイズの目安
python generate_sample.py --out sample_out      # ダミー文書と expected.json だけを生成
```
- `generate_sample.py` は、実在の文書を使わず、日本語名・全角スペース入りの名前・260文字超のパス・リンク・画像のみPDF・暗号化PDF・壊れたファイル・旧形式のダミーなどを含む文書群を作ります。
  仕込んだ内容と、検索語ごとの期待結果（ファイル名・場所）は `expected.json` に出力されます。
- ダミーの限界: パスワード付きOffice（OLE形式の署名だけの疑似ファイル）と、AES暗号化PDF（暗号化辞書だけAESと宣言したダミー）は、本物ではありません。
- GUIのテスト: `xvfb-run python -m unittest tests.test_gui`（Linux）。
