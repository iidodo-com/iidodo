# 窓口番号発券機データ分析ツール — データ仕様・算定ロジック定義書

本書は `dist/madoguchi-analyzer.html` が「どの列を・どの条件で・どう数えているか」を
第三者が数字を検証できる粒度で定義したものです。実装・`tools/make_sample_csv.py`・
`tools/verify.py` はすべて本書の定義に従います。定義を変える場合は本書を先に改訂してください。

参照元：
- 番号発券機テーブル定義書（PDF, 3-1〜3-4節, p.187〜190）
- 実データ1日分 `CD24010400000.CSV`（中区・2024/1/4・683件）による目視検証

---

## 1. 入力ファイル

### 1.1 フォルダ階層とファイル名

```
…/旧端末/令和6年/1月/01中区/CD24010400000.CSV
```

- ファイル名：`CD` + `YYMMDD`（6桁, 対象日） + 支店番号（5桁） + `.CSV`
  - `YYMMDD` の `YY` は西暦下2桁として `2000+YY` に解決する（`24` → 2024年）。
  - 対象日は **ファイル名の YYMMDD** から決定する。フォルダ名の「令和6年」「1月」は
    表示・整合性チェック用の補助情報として使うのみで、日付の一次情報源にはしない
    （和暦→西暦変換の誤りを避けるため）。
  - 支店番号は実データで常に `00000` であり区の判別に使えない。**区は使わない。**
- 区（区コード・区名）は **CSVファイルの直上フォルダ名** から正規表現で取得する。
  - 既定の正規表現：`^(\d{2})(.+)$`（グループ1＝区コード、グループ2＝区名）。
    例：`01中区` → 区コード `01`、区名 `中区`。
  - 設定パネルで正規表現を変更できる。マッチしない場合はフォルダ名全体を区名、
    区コードは出現順の連番とし、「区コード未取得」件数として画面に警告表示する。
- 文字コード：**cp932（Shift_JIS）**。改行：**CRLF**。ヘッダ行なし。**65列固定**。
- 3列目（業種名）のみダブルクォートで囲まれる。単純な `split(',')` は使わず、
  クォート状態を追跡してカンマを数える（3.2節）。
- 探索は再帰的に行い、拡張子が `.CSV`／`.csv` のファイルをすべて対象とする
  （`旧端末` ごと投入しても `令和6年` ごと投入しても同じ結果になる）。

### 1.2 列マッピング（1始まり、既定値）

| 列 | 内容 | 型・備考 |
|---|---|---|
| 1 | 発行番号 | 1〜999。係員呼出・来店カウントは空欄 |
| 2 | 発行業種（大区分） | 1〜32＝通常業務、50〜52＝係員呼出1〜3、60＝来店カウント |
| 3 | 業種名 | 発行大区分業種の名称（クォート付き、cp932） |
| 4 | 発行業種のグループ番号 | 0〜4。0＝係員呼出・来店カウント |
| 5 | 発行時刻 | `HH:MM:SS`。係員呼出・来店カウントでは各々の発生時刻が入る（注3・注4） |
| 40 | 一線呼出時刻 | 未呼出は `0` または空 |
| 41 | 一線終了時刻 | 未確定・未設定は `0` または空 |
| 42 | 取消時刻 | 取消時のみ設定 |
| 48 | 操作状態1（最新） | 0＝未呼出/順呼出、4＝取消、5＝再登録、6＝SKIP、8＝任意呼出 |
| 49 | 操作状態2（1つ前） | 同上のコード体系 |
| 50 | 操作状態3（2つ前） | 同上のコード体系 |
| 51 | 発行時待人数（大区分） | |
| 52 | 呼出時待人数（大区分） | |
| 53 | 呼出テラーアドレス | 実データで16〜37（10進変換後）。空欄あり |
| 65 | カード抜いたフラグ | 1＝抜いた、0＝未抜 |

列番号は上記を初期値とし、設定パネルの「列マッピング」で変更・保存（localStorage）できる。
UIには「1始まり」であることを明記する。

### 1.3 実データで確認された例外パターンと扱い

1. **取消レコード**（操作状態1＝`4`）：呼出時刻・終了時刻・取消時刻が同一値で処理時間が0になる。
   実測683件中8件。**既定で処理時間・時間外算定から除外**する（トグルで含める設定も可）。
   除外件数を常時表示する。
2. **一線終了時刻が空／0のレコード**：実測683件中13件、**全件が16:23以降の発券**。
   閉庁後に呼び出されたまま終了時刻が未記録と考えられる。処理時間・時間外算定に
   直接影響するため、次の3方式を切替可能にし、選択中の方式を常時表示・全出力に記録する。
   - **① 除外**（画面に「過小推計になる可能性」を注記）
   - **② 同一業種・同一区の処理時間中央値で補完**
   - **③ 全体の処理時間中央値で補完**
   中央値は「取消・欠測・外れ値除外後」の母集団から計算する。
3. **大区分50〜52（係員呼出）・60（来店カウント）**：発行時刻欄にそれぞれ係員呼出時刻・
   来店カウント時刻が入り、他項目は0または空欄（注3・注4）。**係員呼出は「窓口内の呼出
   イベント」であり新規来庁ではないため、来庁者母数には常に含めない**。参考値として
   「係員呼出件数」を別途表示する。来店カウント（60）を来庁者母数に含めるかどうかは
   次の母数定義で切替える。
   - **① 発券レコードのみ**：大区分 1〜32 の発行件数
   - **② 来店カウントのみ**：大区分 60 の件数
   - **③ 両方（合算）**：① + ②（二重計上になり得る点を画面に注記）
   現在の母数定義は画面上部に常時表示する。
4. **現行受付時間（8:30〜17:15）外の発券が存在する**（実測最大 17:34:15）。
   時間帯集計のビンは **8:00〜19:00** を確保する（15分刻み、44ビン）。範囲外は
   「集計対象外」として件数を表示する。
5. **処理時間の外れ値**（実測最大226分）。外れ値閾値（分）を設定でき、
   閾値適用前後の代表値（件数・平均・中央値）を並べて表示する。既定閾値は **180分**。

## 2. 用語・派生値の定義

| 用語 | 定義 |
|---|---|
| 来庁時刻 | 列5（発行時刻） |
| 呼出時刻 | 列40（一線呼出時刻） |
| 終了時刻 | 列41（一線終了時刻） |
| 処理時間 | 終了時刻（秒）− 呼出時刻（秒）。負値・0は異常値として除外し件数を計上 |
| 待ち時間 | 呼出時刻（秒）− 発行時刻（秒） |
| 通常業務レコード | 大区分が 1〜32 のレコード |
| 係員呼出レコード | 大区分が 50〜52 のレコード |
| 来店カウントレコード | 大区分が 60 のレコード |
| 取消レコード | 操作状態1（列48）＝ `4` |
| 未呼出レコード | 呼出時刻が空／0 |
| 終了時刻欠測レコード | 通常業務・取消でない・呼出時刻ありだが終了時刻が空／0 |

来庁者数の集計対象（時間帯別グラフ・受付時間スライダー・感度分析マトリクスの母数）は、
上記「母数定義」①②③のいずれかで決まる集合であり、来庁時刻（列5）を基準に15分ビンへ
割り当てる。

## 3. 高速パース仕様

### 3.1 全体方針

1. `navigator.hardwareConcurrency` に応じた数（既定：論理コア数、上限8）のWeb Workerを
   起動し、投入ファイル一覧をラウンドロビンでワーカーに分配して並列パースする。
2. ファイルは `File.arrayBuffer()` で `ArrayBuffer`（バイト列）として読み込む。
   デコードは行わない。
3. 業種名（列3）以外の使用列は数字・コロン・カンマのみのASCII文字なので、
   バイト値から直接数値化する（`String.split` / 正規表現をホットパスで使わない）。
4. 業種名は初出のバイト列をキーにした辞書（`Map`）で一意化し、初回のみ
   `TextDecoder('shift_jis')`（インスタンス使い回し）でデコードして連番IDを割り当てる。
5. 1レコードにつき列指向の `TypedArray`（`Int32Array`／`Uint16Array`／`Uint8Array`）に
   直接格納する。レコードごとのオブジェクトは生成しない。
6. ワーカーからメインスレッドへは `ArrayBuffer` を `Transferable` として
   `postMessage` の第2引数で移譲する（コピーしない）。
7. パース結果とファイル一覧のハッシュを IndexedDB にキャッシュし、2回目以降の起動では
   同一ファイル集合であれば再パースをスキップする。「キャッシュを破棄して再読込」ボタンを
   用意する。
8. 読み込み直後に「日付 × 区 × 15分ビン(96) × 集計カテゴリ」のプリ集約
   `Int32Array` を1回のスキャンで構築する。以後の画面操作（フィルタ・受付時間
   スライダー・感度分析マトリクス・時間外基準時刻の変更）は、この集約配列の
   範囲和だけで応答し、生データは再走査しない。
9. 待ち時間分布・テラー別処理時間分布・繁忙日ランキングは、列指向 `TypedArray`
   （生レコード相当だが依然としてプレーンな数値配列でオブジェクトは持たない）に対する
   単純な線形スキャンで都度計算する。78万件規模でも数十ミリ秒程度で完了するため
   体感上は即時だが、上記8の「事前集約のみを参照する」設計とは異なる点を
   `docs/PERF.md` に明記する。

### 3.2 バイト列からのフィールド抽出

- カンマ（`0x2C`）とダブルクォート（`0x22`）だけを見る1パスのバイトスキャナで、
  各列の開始・終了バイト位置（オフセット表）を作る。
  - `inQuotes` フラグを持ち、クォートに入ったらカンマを区切りとして扱わない
    （`""` はエスケープされたクォート1文字として扱う）。
  - 実データでは列3のみが常時クォートされる。
- 数字列 → 整数：各バイトから `0x30` を引いて桁ごとに `*10` で合成する。
- 時刻 `HH:MM:SS`（8バイト固定） → 真夜中からの秒：
  `((b0-0x30)*10+(b1-0x30))*3600 + ((b3-0x30)*10+(b4-0x30))*60 + ((b6-0x30)*10+(b7-0x30))`。
  列が空、または `"0"` のみの場合は「未設定」として `-1` を格納する。
- 業種名（列3）：クォート内バイト列を取り出し、辞書キー（バイト列を1文字ずつ
  `String.fromCharCode` した簡易キー）で照合。未登録なら
  `TextDecoder('shift_jis').decode(slice)` でデコードして新規IDを割り当てる。

### 3.3 レコードごとに保持するフィールド

| フィールド | 型 | 内容 |
|---|---|---|
| dateIdx | Int32 | 1970-01-01からの通し日数 |
| kuId | Uint8 | 区ID（設定パネルの正規表現で解決した区の登場順連番） |
| daiKubun | Uint8 | 大区分（列2） |
| gyoshuId | Uint16 | 業種名のインターンID（列3） |
| issueSec | Int32 | 発行時刻の秒（列5） |
| callSec | Int32 | 一線呼出時刻の秒、未設定は-1（列40） |
| endSec | Int32 | 一線終了時刻の秒、未設定は-1（列41） |
| op1 | Uint8 | 操作状態1（列48） |
| tellerAddr | Uint8 | 呼出テラーアドレス、未設定は0（列53） |
| fileId | Uint16 | 由来ファイルのID（エラー行の追跡・検証用） |

65列でない行・数値変換に失敗した行は取り込まず、
「ファイル名・行番号・原因（列数不一致／時刻フォーマット不正 等）」を
スキップ一覧としてCSVに書き出せるようにする（黙って捨てない）。

## 4. 分析ロジック

### 4.1 時間帯別来庁者数（15分刻み）

- ビンは 8:00〜19:00 の44ビン（`floor((issueSec-8*3600)/900)`、範囲外は「対象外」に集計）。
- 母数定義①③なら大区分1〜32、②③なら大区分60を計上（4.0節参照）。
- 区・業種（gyoshuId）・期間（dateIdxの範囲）・曜日（`dateIdx % 7` を基準日で解決）で
  フィルタし、区または業種で積み上げる。

### 4.2 受付時間スライダー

- 開始・終了を15分刻み（8:00〜19:00の範囲）で指定。
- 「変更後受付時間内の来庁者数」＝ `[開始,終了)` のビン合計（現在のフィルタ条件込み）。
- 「現行受付時間内来庁者数」＝ 既定 `[8:30,17:15)` の合計（現行受付時間も設定変更可）。
- 比率 ＝ 変更後件数 ÷ 現行件数（×100%）。
- 前半短縮分＝ `[現行開始, 変更後開始)`、後半短縮分＝ `[変更後終了, 現行終了)` の各合計
  （新しい方が短い場合のみ正の値。延長の場合は0または負として扱い「延長」と表示）。

### 4.3 感度分析マトリクス

- 開始時刻・終了時刻を8:00〜19:00の15分刻みで総当たり（開始<終了のみ）。
- 各組み合わせについて、4.2と同じ定義で「対象人数」「現行比カバー率」を算出。
- 「削減見込み時間」＝ 現行受付時間幅（分）− 新受付時間幅（分）（延長時は負値＝増加）。
- 結果はそのままCSV/TSV書き出し可能な表として表示する（説明資料の根拠表を想定）。

### 4.4 時間外勤務削減効果

- 基準時刻（既定16:30、15分刻みで変更可）**以降に発行された**（issueSec ≥ 基準秒）
  通常業務レコード（大区分1〜32）を対象に、処理時間（終了時刻−呼出時刻）を積算する。
- 取消レコードの除外／終了時刻欠測の3方式／外れ値閾値は4.0〜4.5節の定義に従い、
  現在の選択を画面と出力に明記する。
- 区別・月別・業種別（gyoshuId）にピボット集計する。
- 金額換算 ＝ 合計秒 ÷ 3600 × 時間単価（円、入力可）。

### 4.5 待ち時間分布・テラー別処理時間分布

- 待ち時間 ＝ 呼出時刻−発行時刻（callSec≥0 のレコードのみ、取消は既定除外）。
- 処理時間分布はテラーアドレス（列53）別にヒストグラム化する（4.4と同じ処理時間定義）。
- ヒストグラムのビン幅は分単位で可変（既定1分、0〜外れ値閾値の範囲＋「閾値超」ビン）。

### 4.6 繁忙日の特定

- 日別の来庁者数（母数定義に従う）を降順ソートし上位N件（既定20）を表示。
- 月別合計・曜日別合計・月初（1〜5日）／月末（26日〜月末日）平均 と
  それ以外の日の平均を比較する。

## 5. 出力

- 各集計表はCSV/TSV（cp932／UTF-8選択可、Excelでそのまま開ける形式）でダウンロードできる。
- 各グラフはSVG／PNG（背景透過選択可、PowerPoint貼り付け用の高解像度）で書き出せる。
- 説明資料サマリー（`.md`）は、現在のフィルタ・受付時間スライダーの値から
  「変更後受付時間◯:◯〜◯:◯は、現行受付時間内来庁者の◯◯%（◯◯件）に相当する」等の
  文章を自動生成する。
- 分析条件（列マッピング・母数定義・欠測処理方式・外れ値閾値・基準時刻・区名正規表現・
  フィルタ）はJSONでエクスポート／インポートでき、同一条件で同じ数字を再現できる。
- 画面はA4横の印刷レイアウト（`@media print`）に対応する。

## 7. 参考：実データ1日分（中区・2024/1/4・683件）の実測値

自己検証の目安（本ツールの検証にも使用）。

- 発行時刻 08:22:54 〜 17:34:15
- 取消レコード（操作状態1＝4）：8件
- 一線終了時刻が空のレコード：13件（すべて16:23以降の発行）
- 処理時間（終了−呼出、取消8件を除く675件のうち終了時刻ありの662件）：
  平均9.3分／中央値5.0分／最大225.9分
- 待ち時間（呼出−発行）：平均2.2分／最大22.8分
- 16:30以降の発券：49件
