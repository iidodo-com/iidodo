# madoguchi-analyzer — 使い方

窓口番号発券機のCSV（フォルダごと）を投入して、受付時間の変更が来庁者数・時間外勤務に
どう影響するかを分析するツールです。`dist/madoguchi-analyzer.html` 1ファイルだけで
完結し、外部CDN・外部フォント・外部APIには一切アクセスしません。読み込んだデータは
ブラウザの中だけで処理され、外部には送信されません（画面上部に常時表示）。

## 動作環境

- Windows/Mac の Edge または Chrome（最新版）。`file://` で直接開いても動作します。
- 大量データ（8区×1年分・約2,000ファイル）を扱う場合は、メモリに余裕のある端末を推奨します
  （実測値は `docs/PERF.md` を参照）。

## 使い方

1. `dist/madoguchi-analyzer.html` をブラウザで開く（ダブルクリックでOK）。
2. 「令和6年」フォルダ、「旧端末」フォルダなど、CSVを含む任意の階層のフォルダを
   画面の点線エリアにドラッグ＆ドロップする。または「フォルダを選択」ボタンから選ぶ。
   - フォルダの深さは自動判定するので、`旧端末` ごと・`令和6年` ごと・区フォルダ単体、
     どの単位で投入しても同じ結果になります。
3. 読み込み中は進捗バー・処理件数・毎秒行数・残り時間目安が表示されます。
4. 読み込み完了後、画面上部の「設定」パネルで以下を確認・必要に応じて変更します。
   - **列マッピング**：列がずれている場合はここで1始まりの列番号を直接修正します。
   - **区の判定**：直上フォルダ名にマッチさせる正規表現（既定 `^(\d{2})(.+)$`）。
   - **母数定義**：来庁者数を「発券レコードのみ」「来店カウントのみ」「両方」のどれで数えるか。
   - **一線終了時刻が欠測のとき**の扱い（除外／同一業種同区中央値補完／全体中央値補完）。
   - **外れ値閾値**・**取消レコードの扱い**・**時間外算定の基準時刻**・**時間単価**。
   - 変更後は「設定を適用して再集計」を押す。列マッピング・区判定を変更した場合は
     自動的に再パースされます（それ以外の設定は集計のみ再計算するため高速です）。
5. 画面上部のステータスバーには、現在の母数定義・欠測処理方式・外れ値閾値・
   時間外基準・除外件数（取消／欠測／スキップ行）が常時表示されます。
6. 「フィルタ」パネルで区・業種・曜日・期間を絞り込めます（チップをクリックでON/OFF）。
7. 各タブ（①〜⑦）で分析結果を確認し、CSV/TSV・SVG/PNG・.md・JSONで書き出せます。
   - **① 時間帯別来庁者数**：15分刻みの積み上げ棒グラフ。
   - **② 受付時間スライダー**：開始・終了時刻を動かすと即座に影響人数が再計算されます。
   - **③ 感度分析マトリクス**：開始×終了の全組み合わせの影響人数・カバー率の一覧表。
     そのまま説明資料の根拠表として使えます。
   - **④ 時間外勤務削減効果**：基準時刻以降の処理時間を区別・月別・業種別に集計し、
     時間単価で金額換算します。
   - **⑤ 待ち時間・テラー別分布**：呼出待ち時間のヒストグラムとテラー別処理時間。
   - **⑥ 繁忙日の特定**：日別件数ランキング・月別/曜日別傾向・月初月末比較。
   - **⑦ 説明資料サマリー**：②・④の結果から日本語の文章を自動生成し `.md` で保存できます。
8. 「分析条件をJSON出力」で今回の設定一式を保存できます。別の端末や後日、同じJSONを
   読み込めば同じ数字を再現できます。
9. A4横で印刷したい場合は「A4横で印刷」ボタン、またはブラウザの印刷機能を使ってください。

## キャッシュについて

一度読み込んだフォルダ（ファイル名・サイズ・更新日時・列マッピング設定のハッシュ）は
IndexedDBに保存され、同じフォルダを再度投入すると再パースをスキップして即座に表示されます。
列マッピングや区判定の正規表現を変更した場合は自動的に再パースされます。
うまく反映されない場合は「キャッシュを破棄して再読込」ボタンを使ってください。

## 実データ投入前に確認すべきこと

1. **列マッピングの検証**：まず1ファイルだけ投入し、「① 時間帯別来庁者数」の対象件数や
   ステータスバーの除外件数が、Excel等で数えた値と一致するか確認してください。
   列がずれている場合は「発行業種（大区分）」の値が1〜32,50〜52,60以外の値になったり、
   時刻列が不正な値としてスキップされたりするので、スキップ行ログ（画面下部）で
   異常の有無をまず確認するのが早道です。
2. **区名フォルダの判定**：区コードが取得できないフォルダがあると「区コード未取得」の
   警告が出ます。実際のフォルダ命名規則が既定の正規表現（`^(\d{2})(.+)$`）と異なる場合は
   設定パネルで正規表現を調整してください。
3. **母数定義の選択**：本番の説明資料に使う前に、必ず母数定義（① 発券レコードのみ／
   ② 来店カウントのみ／③ 両方）を業務の実態に合わせて選択してください。既定は①です。
   選択中の定義は画面上部に常時表示されます。
4. **欠測終了時刻の扱い**：既定は「①除外」（過小推計になり得る）です。時間外勤務の
   金額を過小に見せないためには②③の中央値補完も試し、結果の幅を確認してください。

## 列マッピングの変更方法

設定パネルの「列マッピング」に、使用する15項目それぞれの列番号（1始まり）を
入力するフィールドがあります。番号発券機の機種・設定が異なり列位置がずれる場合は、
ここを実データに合わせて修正し、「設定を適用して再集計」を押してください
（列マッピングの変更は必ず再パースが走ります）。列の意味は `docs/SPEC.md` の
1.2節を参照してください。

## ダミーデータでの動作確認

```bash
# 小規模（動作確認用）
python3 tools/make_sample_csv.py --out samples/dummy_small --kus 2 --months 1,2 --seed 1

# 大規模（負荷試験用。8区×12か月・約2,000ファイル・約80万件）
python3 tools/make_sample_csv.py --out /path/to/perfdata --kus 8 --months 1-12 \
  --seed 42 --scale full --base-count 340
```

生成された `expected.json` と、ツールの「⑥ 繁忙日の特定」タブから出力した
`日別集計.csv`（母数定義は既定の①のまま）を次のコマンドで突合できます。

```bash
python3 tools/verify.py --expected samples/dummy_small/expected.json --actual 日別集計.csv
```

## 既知の制約

- CP932（Shift_JIS）へのエクスポートは、ブラウザ標準の `TextDecoder('shift_jis')` を
  逆引きしてその場で構築した変換表を使っています（外部の文字コード表は同梱していません）。
  JIS X 0208 の範囲はほぼ網羅していますが、変換表に無い文字は `?` に置き換わります。
- 感度分析マトリクス・時間外勤務の集計は「日付×区×15分ビン×業種」のプリ集約配列を
  使うため、フィルタ操作やスライダー操作は高速に応答します。ただし、待ち時間分布・
  テラー別処理時間分布・繁忙日ランキングは生データ（列指向TypedArray）を都度
  線形スキャンして計算しています。数十万件規模でも数十〜百数十ミリ秒程度で完了しますが、
  「事前集約のみを参照する」設計ではない点を明記しておきます（詳細は `docs/PERF.md`）。
- 65列でないなど数値変換に失敗した行はスキップされ、画面下部のスキップ行ログと
  CSV出力で確認できます。黙って捨てることはありません。
- 印刷レイアウト（A4横）は主要な表を対象にしたシンプルな実装です。複雑な図表の
  印刷位置調整は手動で行ってください。
- PNG書き出しは、SVGをCanvasに描画してから `toBlob()` する方式のため、極端に大きい
  グラフでは書き出しに数百ミリ秒かかることがあります。
