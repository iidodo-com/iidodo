# Excel X-Ray（Excelの検査室）

Excelファイル（`.xlsx` / `.xlsm`）をドラッグ＆ドロップするだけで、通常のExcel画面では見落としやすい **隠れた構造・数式の異常候補・参照関係** を、根拠（シート名・セル番地・数式）つきで表示するWebアプリです。

- **すべてブラウザ内で完結**します。ファイルの読み込み・解析・レポート生成にサーバー、データベース、クラウドストレージ、AI API、外部Web APIは一切使いません（本番ビルドにはCSPを付与し、外部通信を禁止しています）。
- **読取専用**です。元ファイルを変更・上書きしません。マクロは実行せず、外部リンク先へも接続しません。
- 数式の**再計算は行いません**。ファイルに保存されている計算結果だけを参照します。

## セットアップと起動

必要なもの: Node.js 20 以上（22で確認）

```bash
cd excel-xray
npm install          # 初回のみ（以降のアプリ利用中は外部通信なし）

npm run dev          # 開発サーバー  http://localhost:5173
npm run build        # 型チェック + 本番ビルド（dist/）
npm run preview      # 本番ビルドを確認  http://localhost:4173
npm test             # 自動テスト（Vitest）
npm run typecheck    # 型チェックのみ
npm run fixtures     # テスト用Excelを fixtures/ に再生成
```

> `dist/` を `file://` で直接開くとブラウザのモジュール読込制限で動かない場合があります。`npm run preview` か任意の静的サーバーで配信してください。

トップ画面の「サンプルで試す」から、ブラウザ内で生成したサンプルブックをすぐ検査できます。`fixtures/` にも同じテスト用ファイルが入っています。

### 検出の考え方（誤検知を減らす工夫）

- **エラー**: 数式セルのうち、保存された計算結果が `#REF!` `#DIV/0!` `#VALUE!` `#NAME?` `#N/A` `#NUM!` `#NULL!` のものだけを「事実」として報告します。保存結果がない数式は「保存結果なし」として別扱いにし、エラーとは判定しません。
- **パターン不一致**: `@borgar/fx` でトークン化した数式をR1C1（相対位置）形式へ正規化して比較します。`D2=B2*C2` と `D3=B3*C3` は同一パターンなので誤検知しません。絶対参照（`$A$1`）・複合参照（`$A1` `A$1`）・他シート参照・列／行全体参照に対応しています。同一列（行）の連続する数式のうち過半数が同じパターンで、少数だけ異なるセルを候補にします。合計行（範囲を集計する関数）は除外します。「周辺の数式から想定される形」も併記します。
- **固定値混入**: 同じパターンの数式に上下（左右）で挟まれた固定値、または同パターンが3つ以上続いた末尾の固定値を**要確認の候補**として表示します（確定エラーとして扱いません）。見出し・列先頭のパラメータ・合計欄などは対象外になるよう絞っています。
- **判定の確実性**: 「事実（保存内容から確認）」「可能性が高い」「要確認の候補」の3段階で明示します。
- **循環参照**: 静的な参照関係の強連結成分で検出します（「可能性」として表示）。
- **動的参照**: `INDIRECT` / `OFFSET` を含む数式は「依存関係を完全に特定できない」と明示します。

## 技術構成

- React 19 + TypeScript + Vite
- Excel読込: [ExcelJS](https://github.com/exceljs/exceljs)（セル・数式・保存結果・行列の非表示・結合・テーブル・入力規則）と JSZip（`workbook.xml` から シート状態（Very Hidden）・名前定義・外部リンク・再計算フラグを直接読取り）
- 数式解析: [@borgar/fx](https://github.com/borgar/fx)（数式トークナイザ、A1⇄R1C1変換）。正規表現だけに頼らない実装
- グラフ: [@xyflow/react](https://reactflow.dev/)（React Flow）。レイアウトは自前の階層配置
- 重い処理（読込・解析・グラフ探索・差分）は **Web Worker** 内で実行し、操作画面が固まらないようにしています
- テスト: Vitest

```
excel-xray/
├─ src/core/        UI非依存の解析ロジック（parse / formula / formulaTable / analyze / graph / diff / report）
├─ src/worker/      Web Worker とクライアント
├─ src/ui/          画面コンポーネント
├─ scripts/         テスト用Excelの生成（fixtures-lib.ts / make-fixtures.ts）
├─ fixtures/        生成済みテスト用Excel（16ファイル）
└─ tests/           自動テスト
```

## 安全性

- HTMLレポートはすべての値（ファイル名・シート名・セル値・数式）をエスケープし、スクリプトを含まず、CSP（`default-src 'none'`）も付与しています。画面もReactの標準エスケープのみを使い `dangerouslySetInnerHTML` は使用していません。
- CSVは、セルの内容が `=` `+` `-` `@` で始まる場合に先頭へ `'` を付けます（Excelで開いた際の数式インジェクション対策）。
- 本番ビルドのCSPは `connect-src 'self'` のため、外部サーバーへの送信はブラウザが拒否します。

## 制約事項（できないこと・注意点）

- **対応形式は `.xlsx` / `.xlsm` のみ**です。旧形式 `.xls`、`.xlsb`、パスワード保護されたブックは読み込めず、その旨を表示します。`.xls` は信頼できる軽量な読取手段（保守されたライブラリ）と数式忠実度の検証が必要なため、今回は未対応としました。
- **数式を再計算しません。** 値・エラーはファイルに保存された結果です。保存結果がない数式（Excel以外で作成されたファイルなど）は値ベースの検査（エラー判定）ができません。
- 検出されるパターン不一致・固定値混入・空白参照・定数埋め込みは**候補**であり、誤りとは限りません。
- 参照先が実行時に決まる `INDIRECT` / `OFFSET` は依存関係を特定できません。名前定義・テーブル構造化参照は、単純な範囲に解決できる場合のみ依存関係に反映します（構造化参照はテーブル全体への近似）。
- 条件付き書式、グラフ、ピボットテーブル、図形、スライサー、コメント、VBAマクロの内容は検査しません（存在する場合は「検査対象外」に表示）。
- 数式セルに付けられたハイパーリンクは、リンク一覧に表示されない場合があります（数式・保存結果自体は読み取れます）。
- ExcelJSは、数式セルの計算結果が `0` / `false` / 空文字のとき公開API（`cell.value`）で結果を落とす既知の挙動があるため、内部モデルから結果を直接読んでいます。
- 巨大ファイルはメモリを多く使います（150MB超は拒否、30MB超は警告）。セル表は約100万行まで仮想スクロールしますが、ブラウザの要素高さ上限（Firefoxなど）により末尾付近が表示できない場合があります。ノード数・循環参照検査・差分件数・警告の表示件数には上限を設けており、打ち切った場合は画面に明示します。
- 比較機能の「シート名変更」は内容の類似度による**推定**です。
