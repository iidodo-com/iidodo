# 私ならこう答える

広島市 行政経営課職員（本人）が受け取る質問・相談・メール・照会文に対して、本人の立場・判断基準・文体で
書かれた回答案を得るためのローカル実行ツール。汎用AIの一般論ではなく、本人が実際に書きそうな回答を出すことが
唯一の価値であり、そのための唯一の資産が `context/` 配下のプロファイルである。

## 起動手順（ワンクリック）

OSに応じたファイルをダブルクリックするだけで起動する。

- **Windows**：`start.bat` をダブルクリック
- **macOS**：`start.command` をダブルクリック（初回のみ「開発元を確認できません」の警告が出た場合は、右クリック→「開く」を選ぶ）

初回起動時は `.env` が自動生成され、APIキーを貼り付ける画面（メモ帳／テキストエディタ）が自動的に開く。
`ANTHROPIC_API_KEY=` の後に [console.anthropic.com](https://console.anthropic.com) で発行したキーを貼り付けて保存し、
編集画面を閉じると、依存パッケージのインストール（初回のみ）とアプリの起動、ブラウザでの表示までを自動で行う。
2回目以降は `.env` の作成をスキップし、すぐに起動する。

## 起動手順（手動・ターミナル利用時）

```bash
npm install
cp .env.example .env   # ANTHROPIC_API_KEY を設定する
npm run dev
```

表示された URL（既定では http://localhost:5173）を開く。`npm run dev` の1コマンドだけで、
画面（Vite/React）と API プロキシ（Vite dev サーバのミドルウェア、`server/index.ts`）が同時に立ち上がる。
Anthropic API キーはこのミドルウェアの中でだけ使われ、ブラウザに配信されるコードには一切含まれない。

`.env` を後から書き換えた場合、変更を反映するにはアプリの再起動（`start.bat` / `start.command` の再実行、
またはターミナルで `npm run dev` を再実行）が必要（環境変数はプロセス起動時にのみ読み込まれるため）。

## 画面構成

- **回答生成**：質問文などを貼り付けると、①私ならこう答える／②判断の根拠／③触れなかった論点・リスク／
  ④別案、の4ブロックを生成する。相手・場面・長さは任意選択で、未選択なら本文から推定し、推定結果を明示する。
  出力に対して「採用」「修正して採用」「不採用」を記録できる。「修正して採用」時は、修正後の本文との差分から
  再利用可能なルールを抽出し `context/04_learned.md` に反映する。
- **壁打ちモード**：質問文と「本人が書いた答え」の両方を入力すると、代筆はせずに
  (1) 通る／条件付き／通らないの判定と理由、(2) 相手から来る質問の予測（最大3）と返し方、
  (3) 裏取りが必要な箇所、を返す。書き直し案は「直して」ボタンを明示的に押したときだけ生成し、
  元の文体・語順を保持したまま変更箇所と理由をセットで示す。
- **履歴**：`data/history.json` に保存された生成結果を検索・閲覧し、回答生成モードの入力として呼び戻せる。

## context の育て方（このアプリの中核）

```
context/
  00_persona.md    立場・経歴・価値観・動機。人が編集する。
  01_style.md      文体・回答作法のルール。人が編集する。
  02_projects.md   進行中の案件と論点。変わりやすいので定期的に人が更新する。
  03_precedents.md 過去の判断事例。判断に迷ったら追記する。
  04_learned.md    フィードバックからアプリが自動追記する学習メモ。基本的に人が直接編集しない。
```

- `00〜03` は人が直接編集するファイル。誤りに気づいたら本人が直接書き換える。
- 画面上部の「contextをリロード」ボタンを押すと、アプリを再起動せずに編集内容が次回生成から反映される
  （サーバは起動時に一度読み込んでキャッシュしており、このボタンを押すまでは編集前の内容のままになる点に注意）。
- `04_learned.md` は「修正して採用」を選ぶたびに、AIが元案と修正後の差分から
  「上司宛では前置きの謝辞を入れない」のような反証可能な粒度のルールを1行だけ抽出して追記・更新する。
  一般論（「丁寧に書く」等）は抽出されない設計。同義のルールが既にある場合は追記せず既存行を更新する。
- 出力が一般的なAIの回答に寄ってきたと感じたら、まずは `02_projects.md`（案件の前提が古い）と
  `03_precedents.md`（判断の型の実例が足りない）を疑って追記する。

## 情報の取扱い上の注意

- `context/` と `data/history.json` には、人事評価・調達判断・案件の内部論点など機微な内容が含まれる。
  `data/` は `.gitignore` 対象なのでリポジトリにはコミットされないが、ローカルディスク上には平文で残る。
  端末の取扱いには注意すること。
- `.env`（APIキー）はコミットしない。誤ってコミットした場合は速やかにキーを失効・再発行すること。
- 生成結果は「本人が実際に書きそうな下書き」であり、事実関係の断定を含む場合がある。
  `【要確認：〇〇】` と明示された箇所は必ず裏取りしてから使用する。送信前の最終責任は本人にある。

## 技術構成

- Vite + React + TypeScript + Tailwind CSS（1ページ完結、タブでモード切替）。
- API 呼び出しは `server/index.ts`（Vite dev サーバのミドルウェアとして実装）が一括して担い、
  `src/lib/prompt.ts` で組み立てたシステムプロンプト＋ `context/*.md` を Anthropic Messages API に渡す。
  モデルは既定で `claude-sonnet-4-6`（`.env` の `ANTHROPIC_MODEL` で変更可）。
- 生成結果は `data/history.json` に追記保存する。

## 既知の制約

- API プロキシは Vite の dev サーバのミドルウェアとして実装しているため、`npm run build` で作る静的ビルドを
  そのまま配信しても API は動かない。本ツールはローカルでの `npm run dev` 利用を前提としている。
- 壁打ちモードには、回答生成モードのような「採用／修正して採用／不採用」評価は付けていない
  （壁打ちの成果物は講評であって再利用可能な回答案ではないため）。
- 履歴の検索は `data/history.json` 全件をクライアント側でフィルタする簡易実装。運用が長期化し件数が増えた
  場合はページングや期間絞り込みの追加を検討する。
