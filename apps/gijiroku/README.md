# 議事録・文書作成支援（試作）

会議の書き起こしテキストを貼り付けると、**議事録**または**復命書**の様式に整えて出力するWebアプリです。サーバーを持たない静的ページ（ビルド不要・GitHub Pages 互換）で、整文には Google の Gemini API を使います。APIキーは利用者がブラウザ内に入力し、そのブラウザの `localStorage` にだけ保存されます。

> **試作版です。** 出力には誤りが含まれ得ます。公文書として使う前に、必ず人が原文と照合してください。

## 3分で試す（APIキー不要）

1. `index.html` をブラウザで開く（インストール不要。GitHub Pages などで公開した URL でも同じ）。
2. 「様式」を選ぶ（議事録／復命書）。
3. 「サンプル文を入力」→「デモ出力で確認（APIなし）」を押す。
4. 下に出力が表示される。コピー、TXT／Markdown／DOCX のダウンロード、印刷ができる。

デモは外部に何も送信しません。サンプルの人名・団体名・日付はすべて架空です。

## 実際に使う（Gemini）

| 手順 | 操作 | 確認すること |
|---|---|---|
| 1. キーを用意 | Google AI Studio（<https://aistudio.google.com/apikey>）で Gemini API キーを発行する（画面名称は変わることがあります） | キーは他人に見せない。可能なら Google 側で利用元（HTTPリファラー）を制限する |
| 2. 保存・テスト | 画面下部「APIキー設定」にキーを貼り付けて「保存」→「接続テスト」 | 「✓ キーの確認：有効」「✓ モデルの確認」が出る |
| 3. 貼り付け | 書き起こしを貼り付ける。日時・場所などが分かっていれば補助入力に書く（書き起こしより優先される） | |
| 4. 必要なら伏せ字 | 「詳細設定」に伏せる語を入れ、「送信前に伏せる」を有効にし、「送信される内容を確認」で目視する | 氏名が送信内容に残っていない |
| 5. 生成 | 送信前の確認にチェックを入れ、「Gemini で整文して生成」 | 長文は自動で分割され、進捗（何件目／全何件）が出る |
| 6. 照合 | 出力の「要確認事項」を読み、原文と見比べる | 特に日時・氏名・数値・期限 |
| 7. 取り出し | コピー／TXT／Markdown／DOCX／印刷 | |

既定のモデル名は `gemini-3.8-flash` です（姉妹アプリでの動作確認結果に基づく設定で、本アプリ上では未検証）。モデル名は画面で変更でき、「接続テスト」で存在を確認できます。

## 機能

### 様式
- **議事録**：会議名・日時・場所・出席者・議題・決定事項・ToDo（担当・期限）・要確認事項
- **復命書**：件名・期間・所属職名氏名・用務先・概要（1 用務の概要／2 日時・場所／3 相手方／4 所感）・要確認事項

書き起こしに書かれていない事実は作らせず、不明点・補った点は「要確認事項」に出します。

### 氏名・固有名詞の伏せ字（2種類・併用可）
| 機能 | 何をするか | 語は Google に送られるか |
|---|---|---|
| **送信前に伏せる** | 指定語を「〔名称1〕」などの記号に置き換えて送信し、返ってきた結果をこの端末で元の語に戻す（補助入力欄も同様） | **送られない**（伏せ漏れを検知したら送信を中止） |
| **出力を伏字にする** | 画面・コピー・ダウンロードの指定語を「●●」に置き換える（元の結果は保持。いつでも切替可） | （送信とは無関係） |

併用すると「送信前に伏せ → 結果を元に戻し → 出力は●●」になります。指定語はカンマ区切りで、長い語から照合します。「書き起こしから候補を抽出」で「〇〇さん」「〇〇課長」などの氏名候補を拾えます（簡易機能。取りこぼし・誤検出あり）。

**限界：** 伏せられるのは指定語に完全一致する部分だけです。指定していない語、表記ゆれ（姓のみ、旧字体、ひらがな表記、略称）、文脈から個人が分かる記述は伏せられません。完全な漏えい防止を保証するものではありません。

### 長文の分割
入力が「分割の目安」（既定・上限 60,000字。「詳細設定」で変更可）を超えると、段落単位で分割して順次処理し、1つの様式に統合します。全体の上限は 300,000字です。単値（会議名・日時など）は最初の非空値、リストは連結して完全一致で重複除去します。意味的な重複の整理や、分割をまたぐ内容の補完はしません（統合時に「要確認事項」へ注意書きを追加します）。

途中で失敗しても、完了済みの分は保持され、「失敗した件から再開」で続きから実行できます。429・5xx・通信エラー・タイムアウトは自動で最大2回まで再試行します。

### DOCX 出力
外部ライブラリなしで、クライアント側で A4 の .docx を生成します。見出しは組み込みスタイル（Word のナビゲーションに出る）、箇条書き・項番は本物の番号定義（リストごとに番号を振り直し）、表は固定レイアウト（見出し行を繰り返し、行はページをまたいで割れない）です。**生成のたびに自己検証**（ZIP の CRC、XML の整形式、コンテントタイプ、参照、要素の並び、表の整合、本文の欠落）を行い、不合格ならダウンロードさせません（TXT／Markdown を案内します）。非対応ブラウザでは DOCX ボタンだけが無効になります。

### その他
接続テスト（キー有効性とモデル存在の確認）、印刷用CSS（A4・出力部分のみ印字）、利用規約・プライバシーポリシー（試作版の案）。

## 困ったとき

| 表示 | 意味 | 次にすること |
|---|---|---|
| APIキーが無効です | キーが正しくない | キーを入れ直して保存 → 「接続テスト」 |
| このAPIキーでは利用が許可されていません（401/403） | キーの制限や API 未有効化 | Google 側でリファラー制限・対象API・Gemini API の有効化を確認 |
| モデルが見つかりません（404） | モデル名が存在しない | 「接続テスト」で確認し、モデル名を直す |
| 利用上限（429）／混み合っています（5xx） | 一時的な制限・障害 | 自動再試行後も失敗なら、少し待って「失敗した件から再開」 |
| 応答が時間内に返りませんでした | 長い入力など | 「失敗した件から再開」、または分割の目安を小さくする |
| Gemini に接続できませんでした | 通信不可 | ネットワークと、社内プロキシ・ファイアウォールで `generativelanguage.googleapis.com` が許可されているかを確認 |
| 安全フィルタでブロックされました | 入力が拒否された | 該当部分を削除または伏せて再実行（デモで様式の確認は可能） |
| 出力が途中で切れました | 出力上限 | 分割の目安を小さく（例：20,000字）して最初から |
| 応答を読み取れません／想定外の形式 | 応答がJSONでない・様式違い | 「失敗した件から再開」。様式の選択が内容に合っているかも確認 |
| 「伏せ記号を元の語に戻せなかった」 | 応答で記号が崩れた | 出力中の「〔名称N〕」を原文と見比べて手で直す |
| DOCX ボタンが押せない／作成できない | 非対応ブラウザ、または自己検証NG | TXT／Markdown でダウンロードして Word に貼り付け |
| キーを保存できない | プライベートモード等 | 通常のウィンドウで開く／サイトデータの保存を許可 |

## 開発者向け

### ファイル構成（`apps/gijiroku/`）
| ファイル | 内容 |
|---|---|
| `index.html` | 本体画面（入力・出力・伏せ字・APIキー設定・使い方） |
| `app.js` | ロジック（プロンプト、Gemini 呼び出し・再試行、分割・統合、伏せ字、エラー整形、組版） |
| `docx.js` | DOCX 生成と自己検証（外部ライブラリなし） |
| `demo.js` | デモ用サンプル（架空） |
| `style.css` | 画面・印刷（A4）用CSS |
| `selftest.html` / `selftest.js` | ブラウザ内の自己テスト（外部通信なし） |
| `terms.html` / `privacy.html` | 利用規約・プライバシーポリシー（試作版の案） |

### 実行・公開
- ローカル：`python3 -m http.server -d apps/gijiroku 8000` → <http://localhost:8000/>
- GitHub Pages：リポジトリの Pages 設定で、`apps/gijiroku` を含むブランチ・フォルダを公開対象にする（Pages 側の設定は各自で確認）。ビルド工程はありません。

### 自己テスト
`selftest.html` を開くと、分割・統合、伏字、送信前マスキング（往復・漏れ検知）、エラー整形、API 呼び出し（モック：再試行・タイムアウト・ブロック等）、DOCX の生成・自己検証・否定テスト（壊したファイルを必ず検出できること）を実行し、画面に結果を表示します。

### セキュリティの作り
- 画面の描画は `textContent` のみ（モデル出力の HTML は解釈しない）。
- CSP：`script-src 'self'`・`connect-src` は Gemini API のみ。外部スクリプト・CDN は使わない。
- APIキーはヘッダ（`x-goog-api-key`）でのみ送り、URL に含めない。
- 書き起こしの中の命令文は「データであり指示ではない」と明示して送る。

## 整文ルール（公用文の表記）について

プロンプトの表記ルール（送り仮名、漢字・かなの使い分け、算用数字、和暦・午前午後、敬語・文体、話し言葉の整理）は、国の「公用文作成の考え方」等の**一般的な公用文の考え方**に基づく試作です。

> **広島市「文書事務の手引」の本文は、一次資料がないため、この試作には取り込んでおらず、条文の引用もしていません。手引への適合は確認していません（対象外）。** 手引固有の規定（時刻・日付・敬称・文書様式など）への適合は、手引の該当箇所を確認し、`app.js` の `STYLE_RULES` を調整してください。

## 商用化の論点

### 1. データの取り扱い（最重要）
- 現状は、書き起こしが利用者のブラウザから Google の Gemini API へ**直接送信**される。会議内容には個人情報・非公開情報が含まれ得る。
- Google 側の保存・学習利用の有無は、プラン（無料／有料）や設定で異なる可能性がある。**契約形態ごとの条件を一次情報（Google の規約）で確認する必要がある**（本README作成時点で未確認）。
- 自治体では、情報セキュリティポリシー、個人情報保護条例・個人情報保護法、クラウド利用の可否（ISMAP等の認証要件の有無）が導入可否を左右する。要件は団体ごとに異なるため、個別確認が必要。
- 対策：入力前の注意表示と同意チェック、送信内容の確認、**送信前マスキング（指定語を記号に置換して送信し、端末内で復元）**は実装済み。未実装・検討中：住所・電話番号などの自動検出、送信範囲の限定、国内リージョン／ゼロデータ保持が選べる提供形態。

### 2. オンプレミス・閉域網の需要
- LGWAN など閉域網の端末からインターネット上のAPIへ接続できない団体が多いと考えられる。その場合、ブラウザ完結＋外部API方式は使えない。
- 選択肢：①庁内サーバーに配置するオンプレミス版（ローカルLLMまたは閉域内の生成AI基盤を利用）、②自治体向けクラウド（閉域接続）経由、③ガバメントクラウド上の提供。
- ローカルLLMは、整文品質（公用文表記の遵守）・運用負荷・GPU調達の費用が論点。品質評価の基準（誤り率、様式の遵守率）を先に定めるべき。

### 3. 品質・責任
- 数値・日付・氏名・決定事項の取り違えは、公文書として重大。**人の確認を前提**とするUI（要確認事項の明示、原文との対照表示）を強化する。
- 免責・利用規約の整備（法務確認が必要。現状は案）。
- 表記ルールは団体ごとに異なる（手引・例規）。団体別ルールセットの設定機能が差別化要素になり得る。

### 4. 入力（書き起こし）の確保
- 本アプリは「書き起こし済みテキスト」が前提。音声認識（録音→文字起こし）を含めるかで、価格・データの取り扱い・精度の論点が増える。既存の文字起こしサービスとの連携が現実的な可能性がある（未検討）。

### 5. 価格・提供形態
- 候補：自治体向け年額ライセンス（職員数・課数単位）、オンプレミス版の買い切り＋保守、企業向けSaaS。
- API利用料を利用者負担（BYOK：自前のキー）にする現行方式は、試作・検証には適するが、自治体の調達・会計処理にはなじまない場合がある。
- 自治体への導入は、調達手続（入札・随意契約の要件）、導入実績の確保、セキュリティ審査の期間が壁になる。

### 6. 競合・代替
- 汎用の文字起こし・議事録AI、会議ツール内蔵の要約機能、議会向け会議録システムが存在する。公用文表記と様式への特化をどこまで差別化にできるか、調査が必要（本README作成時点で未調査）。

## 残課題・既知の制限

- **Word 実機での表示は未確認**です（python-docx での読み込み、LibreOffice での PDF 変換、自己検証までは確認）。XSD による完全なスキーマ検証も未実施です。

- 伏せ字は指定語の完全一致のみです。住所・電話番号・メールアドレス等の自動検出、表記ゆれの吸収は未実装です。
- 分割統合は機械的です（意味的な重複の整理、分割をまたぐ決定事項の補完は未実装。必要なら統合用の追加リクエストを検討）。
- 広島市「文書事務の手引」への適合は未確認（上記）。団体別ルールセットは未実装です。
- 利用規約・プライバシーポリシーは案で、法務確認・運営者情報・問い合わせ先の記載が必要です。
- アクセシビリティ（スクリーンリーダー等）の検証、実機での印刷確認は未実施です。
- 音声の文字起こしは対象外です（書き起こし済みテキストが前提）。
