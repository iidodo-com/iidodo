# 文字起こしアプリ商用版（試作）

音声ファイルを取り込み、Gemini API で **文字起こし全文／整文／要約／決定事項とToDo** を一括出力する静的Webアプリの試作です。
ビルド不要・サーバー不要・GitHub Pages 互換（すべて相対パス）。

> ⚠ **試作です。** 実 Gemini API での動作は未検証（後述「検証状況」）。利用規約・プライバシーポリシー・料金ページは**ダミー/ひな形**で、法務確認を受けていません。

## 起動方法

```bash
cd apps/mojiokoshi-pro
python3 -m http.server 8000   # → http://localhost:8000/
```

`file://` では Service Worker（PWA）が動きません。HTTP(S) 経由で開いてください。GitHub Pages では `https://<user>.github.io/<repo>/apps/mojiokoshi-pro/` で動作する想定です（相対パスのみ使用）。

### デモモードで全フローを確認
APIキー未設定のままで OK。画面上部に「デモモード」が表示されます。
1. 「文字起こし」→「ファイル無しでサンプルを試す」（または任意の音声ファイルを選ぶと実際の音量チェックが走ります）
2. 「文字起こしを実行」→ 結果画面（4タブ）へ。話者名変更・発言ごとの話者付け替え・コピー・TXT/MD保存
3. 「履歴」で検索・再表示・削除

## 実APIの使い方
「設定」でGemini APIキーを入力して保存（localStorage のみに保存。コードには埋め込まれていません）。キーがあってもデモにしたい場合は「デモモードを強制」。

## 機能と仕様

| 要件 | 実装 |
|---|---|
| 音声取込＋Gemini呼び出し | `js/gemini.js`。14MB以下は `generateContent` に base64 の `inlineData` で送信。**14MB超〜200MBは Files API**（resumable アップロード → `state` が ACTIVE になるまでポーリング → `fileData` で参照 → 生成後に削除を試行）。進捗（アップロード%・処理待ち経過）を表示し、失敗時は理由を表示。JSON スキーマ指定（`responseMimeType`/`responseSchema`）で4部構成を取得。キーは `x-goog-api-key` ヘッダ（URLに載せない）。50MB超は音量解析を省略（メモリ対策） |
| 接続テスト | 設定画面。入力中のキーとモデルで `models.get` を実行し、キーの有効性・モデルの存在・`generateContent` 対応を表示（推論は行わず課金対象の生成なし）。キー未入力時は通信しない。**音声入力への対応は確認できない** |
| 本文編集 | 文字起こし全文・整文・要約・決定事項を直接編集可（履歴へ自動保存、コピー/TXT/MD出力に反映）。編集した発言は「編集済」表示、「要確認」は【聞き取れませんでした】が消えると解除。話者の付け替えとは同じデータを更新するだけで競合しない |
| モデル切替 | 既定 `gemini-3.8-flash`／代替 `gemini-3.5-flash`／カスタムID入力（設定画面） |
| 4部構成 | 文字起こし全文・整文・要約・決定事項とToDo（タブ表示） |
| 捏造対策 | システムプロンプトで「推測禁止・聞き取れない箇所は `【聞き取れませんでした】`・全く聞き取れなければ他項目は空」を明示。`uncertain` フラグで「要確認」表示。要約/ToDoは発話で明示された事項のみ、担当・期限は不明なら「不明」。結果画面に警告表示（後述） |
| 音量チェック | `js/audio.js`。ブラウザ内でデコードし、有音部RMS・ピーク・無音割合・クリッピングを算出、波形表示。「問題あり」の場合は明示チェックをしないと実行不可。**音声は解析時点では外部送信しない** |
| 話者ラベル | 話者名の一括変更（ToDo担当者表記にも追従）、発言ごとのプルダウン付け替え、話者追加 |
| 履歴 | localStorage（最大200件）。全文検索（ファイル名・話者・本文・要約・ToDo）、再表示、削除、全削除。編集内容も保存 |
| 出力 | タブ単位／全体コピー、TXT／Markdown ダウンロード |
| デモモード | キー未設定または強制ON時、モックデータ（架空の会議）で全フローが通る |
| 製品体裁 | ヘッダー、使い方、料金（ダミー）、利用規約・プライバシー（ひな形）、PWA（manifest＋Service Worker＋仮アイコン） |

### 捏造対策の限界（重要）
プロンプトとスキーマでの抑制は**確率的な低減策**であり、捏造が起きないことを保証しません。そのため UI 側でも (1) 「要確認」表示、(2) 音量が「問題あり」の音声は結果画面に警告、(3) 音量が極小なのに聞き取れなかった箇所がゼロの場合に追加警告、を出します。本番前に、無音・雑音のみ・小声・多話者の評価音声セットで**捏造率を実測**してください。

## 検証状況（正直な記録）

- **確認済み（Playwright/Chromium・ヘッドレス）**: デモモード全フロー、音量チェック（実WAV: 正常/極小/無音）、話者の変更・付け替え、4タブ表示、コピー、TXT/MDダウンロード、履歴の検索/再表示、各静的ページ、設定。さらに **Gemini API をモックした**状態で、リクエスト（URL・ヘッダ・プロンプト・音声MIME）とレスポンスの正規化、429エラー表示まで確認。
- **未確認**:
  - **Files API 経路の実通信**: リクエスト手順は公式の REST 仕様に沿って実装し、モックでの手順・ヘッダ・fileData 参照・FAILED/アップロード失敗時の表示までは確認済みですが、**実際の Google サーバーとの疎通は未確認**です。特に、ブラウザから resumable アップロードのレスポンスヘッダ `X-Goog-Upload-URL` を読めるか（CORS）は実環境で要確認です（読めない場合は「アップロード先URLを取得できませんでした」と表示されます。その場合はサーバー経由のアップロードが必要）。
  - **接続テスト**の実通信（`models.get` の応答形式・エラー本文によるキー不正の判別）。
  - **実際の Gemini API との疎通**（この環境では実キーでの呼び出しを行っていません）。リクエスト形式は公式REST仕様に基づく実装ですが、実測が必要です。
  - **モデルID**: Google公式モデル一覧（ai.google.dev/gemini-api/docs/models）で `gemini-3.8-flash` の記載は確認できましたが、`gemini-3.5-flash` は同ページに**見当たりませんでした**（`gemini-3.5-flash-lite`・`gemini-3.6-flash`・文字起こし向け `gemini-3.5-transcribe` の記載はあり）。代替モデルが実在しない/廃止の場合は 404 になるため、設定の「カスタム」でIDを変更してください。また一覧ページ上で各モデルの音声入力対応が明記されていないため、**音声入力対応は実測で確認が必要**です。公式一覧は随時変わります。
  - m4a 等の MIME 対応（`audio/mp4` として送信）、日本語ファイル名でのダウンロード名（ヘッドレス Chromium では `download` になる現象を確認。実ブラウザでの挙動は未確認）、PWAインストール、iOS Safari の挙動。
  - 音量しきい値（`js/audio.js` の `TH`）は経験則で、実録音での較正が必要。

## 既知の制限
- 音声サイズ上限は 200MB（本アプリの保守的な設定値）。Files API の公式上限とは別。ブラウザ内で全体を1リクエストで送るため、不安定な回線では失敗しやすい（再開・分割アップロードは未実装）。
- 話者分離はモデルの出力に依存（精度保証なし）。話者の誤りは手動で修正。
- 編集履歴（元のAI出力との差分表示・元に戻す）は未対応。編集は上書き保存。
- 履歴は端末ローカル（容量は localStorage 上限、通常 5MB 前後）。端末間同期・バックアップなし。
- APIキーは localStorage に平文保存。同一オリジンのXSSや共用PCではリスクがある。
