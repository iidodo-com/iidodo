# 決算ウォッチ（試作 / 商用リリース候補）

個人投資家向けに、**ウォッチ銘柄の決算予定を管理し、決算通過後のチェックを記録する**静的Webアプリです。
投資スタイルの前提は「**決算を跨がず、通過確認してから判断する**」。売買の推奨や判定は行いません（投資助言ではありません）。

- ビルド不要・サーバ不要。ブラウザだけで動きます（GitHub Pages 互換）
- データはお使いのブラウザ（localStorage）にだけ保存。アカウント登録なし
- **初期表示の銘柄・決算日はすべてダミー（架空）です。実際の決算発表日ではありません**

## 1. 5分で始める

**方法A（最も簡単）**: `apps/kessan-watch/index.html` をブラウザで開くだけ。
**方法B（ローカルサーバ）**: 
```bash
cd apps/kessan-watch
python3 -m http.server 8000   # → http://localhost:8000/ を開く
```
開くとサンプル14銘柄（半導体・AI関連）とダミーの決算日が入っています。次を試してみてください。

1. 「**カレンダー**」タブで決算日を確認 → 銘柄をクリック
2. 「**通過チェック**」タブで「通過済・要確認」の銘柄をクリックし、3欄を記録して「通過確認済みにする」
3. 「**ウォッチ銘柄**」→「銘柄を追加」で自分の銘柄を登録し、決算日を手入力
4. 不要なサンプル銘柄は「ウォッチ銘柄」タブで削除（「サンプルに戻す」は全データを初期化するので注意）

> 本物の決算日を自動で取り込みたい場合は [4章](#4-実データj-quantsを使う)（J-Quants のAPIキーが必要）。使わない場合は、各社のIR情報で決算日を確認して手入力します。

## 2. 画面と基本の流れ

| タブ | できること |
|---|---|
| **リスト** | 決算日順の一覧。「これから発表／通過済・要確認」で絞り込み。行クリックでチェック画面 |
| **カレンダー** | 月表示。日付ごとの銘柄チップをクリックでチェック画面。前月／翌月／今月 |
| **通過チェック** | 決算日を過ぎた銘柄の一覧と、記録の進み具合（n/3 欄） |
| **ウォッチ銘柄** | 登録・編集・削除。「次回決算日」が無い銘柄は「予定未設定」と表示され、「予定を追加」から手入力 |

ツールバー: **銘柄を追加** ／ **予定を再取得**（取得元から最新を取り直す）／ **ICS出力** ／ **設定**。
画面上部の小さな文字に「取得元」と「最終取得時刻」が出ます。

**状態の見方**: `あと◯日` → `あと◯日（設定した警戒日数内）` → `本日発表` → `通過済・要確認` → `通過確認済`。
「警戒日数」は設定で変えられる**あなた自身のルール用の目印**です（既定7日）。売買の指示ではありません。

## 3. 通過チェックの使い方

決算発表の後に、次の3欄を**自分の言葉**で記録します。各欄の「自己評価」（良好／中立／懸念）は整理用ラベルで、アプリが評価するものではありません。

| 欄 | 書く内容の例 |
|---|---|
| ① 実績（売上・利益） | 売上高・営業利益・純利益の結果、会社予想やコンセンサスとの差、前年比 |
| ② ガイダンス | 通期予想の修正の有無、次の四半期の見通し、経営陣のコメント |
| ③ 株価反応 | 発表後の値動き（寄付き・終値）、出来高、自分の所感 |

3欄を確認したら「通過確認済みにする」にチェック → 一覧の状態が緑の「通過確認済」になります。
「自分の判断メモ」には、ルールに照らした所感を書けます（例: 通過を確認できたので次の判断材料に進む／見送る）。

**推奨の運用例**: ①ウォッチ銘柄の決算日を登録 → ②警戒日数内に入ったら、ご自身のルールに従って保有・新規を整理 → ③発表後に3欄を記録 → ④確認済みにしてから判断。

## 4. 実データ（J-Quants）を使う

J-Quants（JPX）の「決算発表予定日」APIから、**日本株**の決算予定を自動取得できます。**ご自身のAPIキー**が必要です（本アプリには何も同梱されていません）。

1. J-Quants に登録し、ダッシュボードの「設定 » APIキー」からAPIキーを発行する（検索結果の記載に基づく案内。実際の画面は J-Quants 公式を確認してください）。利用できるプラン・データ範囲・利用規約も公式で確認してください
2. 本アプリの「**設定**」を開く
3. 「データ取得元」で **J-Quants API V2** を選び、**APIキー**を貼り付けて「保存して再取得」
4. 取得に成功すると、一覧が実データに置き換わり、ダミー表示バナーが消えます

**取得の仕組み**
- 日本株（4桁コード）の登録銘柄を1件ずつ問い合わせます。米国銘柄は対象外（警告が出ます。手入力で登録できます）
- J-Quants は予定日の**変更履歴**を返します。決算区分ごとに**最新の公表日**のレコードを採用します（延期で「未定」になった場合は予定なし）
- 表示するのは「直近の今後の予定1件」と「直近45日以内に通過した1件」
- **手入力した予定は取得結果より常に優先**されます
- 通過チェックを記録した予定は、取得結果から消えても一覧に残ります（記録に辿れなくなるのを防ぐため）

**失敗したとき（障害時の動作）**
- 画面上部に赤いバナーで **失敗理由**・**対処方法**・**再試行ボタン**が出ます
- **既存の予定・チェック記録・手入力の予定は一切変更されません**（「前回の状態のまま保持」と最終取得時刻も表示）
- 一部の銘柄だけ失敗した場合、成功した銘柄は更新し、失敗した銘柄は前回の表示を保持します
- 「ダミーデータに切り替える」で、明示的にダミーへ切り替えられます（自動では切り替わりません。ダミーの日付を実データと誤認しないため）

APIキーは**このブラウザの localStorage にのみ**保存され、api.jquants.com 以外には送られません。バックアップJSONにも含まれません。共用PCでは入力しないでください。

## 5. うまくいかないとき

| 表示 | 原因の目安 | 対処 |
|---|---|---|
| APIキーが未入力です | キー未設定 | 設定でキーを入力して保存 |
| 認証エラー (401/403) | キーが無効・コピーミス・プランの権限外 | 前後の空白を除いて貼り直す。J-Quants側でキーとプランを確認 |
| リクエスト不正 (400) | コード不正、またはプランの参照可能期間外 | 銘柄コードを確認 |
| リクエスト過多 (429) | 短時間の取得しすぎ | 数分待って「再試行」。銘柄を分けて取得 |
| J-Quants側のエラー (5xx) | サービス側の障害 | 時間をおいて「再試行」。自動で1回だけ再試行済み |
| 通信に失敗しました | オフライン、または**ブラウザのCORS制限** | 接続を確認して再試行。繰り返す場合はブラウザ直接接続では利用できない可能性（[検証状況](#10-検証状況何を確認し何が未確認か)）。ダミー切替か手入力で運用 |
| 応答がありません（タイムアウト） | 15秒応答なし | 回線を確認して再試行 |
| 予定未設定 | その銘柄の予定が取得できていない／未登録 | 「予定を追加」から手入力 |
| 表示が消えた・保存されない | ブラウザのデータ削除、プライベートモード | [7章](#7-データの保存バックアッププライバシー)のバックアップから復元 |

## 6. カレンダーアプリへ取り込む（ICS）

「**ICS出力**」ボタンで、**いま表示している予定**を `.ics` ファイルに保存します。

| 現在のタブ | 出力される範囲 |
|---|---|
| リスト | 絞り込み後の一覧 |
| カレンダー | 表示中の月 |
| 通過チェック | 通過済み一覧 |
| ウォッチ銘柄 | すべての予定 |

- 各予定は**終日イベント**。件名は `決算 銘柄名(コード) 対象期`。ダミー由来は `【ダミー】` が付きます
- 取り込み例（Googleカレンダー）: 設定 → インポート/エクスポート → インポート → ファイルを選択。他のアプリは「iCalendar/.ics のインポート」を探してください（画面構成は変わることがあります。実際のアプリでの取り込みは未確認です）
- 同じ銘柄・対象期は同じ予定ID（UID）で出力されるため、日付が変わった後に再出力して取り込むと、対応アプリでは**更新**として扱われます（アプリによっては重複することがあります）
- 取り込んだ予定は**本アプリとは同期されません**（一方向の書き出し）。決算日が変わったら再出力してください

## 7. データの保存・バックアップ・プライバシー

- 保存先: ブラウザの localStorage（このPC・このブラウザ・このアドレスごと）。サーバには送信されません
- ブラウザのデータ消去、別ブラウザ・別端末、`file://` と `http://localhost` の違いで**データは別物になります**。定期的に「**バックアップ書出**」でJSONを保存してください
- 「バックアップ読込」は内容を検証し、壊れた項目を除いて読み込みます（現在のデータは置き換わります）
- 詳細は `privacy.html`（プライバシーポリシー）、`terms.html`（利用規約）。**どちらも試作用ドラフトで、公開前に専門家の確認が必要です**

## 8. よくある質問

**Q. このアプリは売買の判断をしてくれますか？** いいえ。決算日の管理と、あなた自身の記録を整理するだけです。買い／売り判定、目標株価、推奨は出しません。
**Q. 決算日は正確ですか？** ダミーは架空です。J-Quants 取得分も、変更される場合があるため、必ず各社の公式IRで確認してください。
**Q. 米国株は？** 自動取得は未対応です。決算日を手入力すれば、カレンダー・チェック・ICSは同じように使えます。
**Q. 複数の端末で使えますか？** 現状は端末ごとに独立です。バックアップJSONで移行できます。
**Q. 取得元を変えるとチェック記録はどうなりますか？** 記録は残ります。記録済みの予定は取得結果に無くても一覧に残ります。

## 9. 開発者向け

```
apps/kessan-watch/
├─ index.html / help.html / terms.html / privacy.html
├─ css/style.css
├─ data/sample.js        # ダミーデータ（相対日で生成）
├─ js/
│  ├─ adapters.js        # EarningsAdapter interface・ダミー・J-Quants V2
│  ├─ ics.js             # ICS生成（RFC 5545）
│  ├─ storage.js         # localStorage＋入力検証(sanitize)
│  └─ app.js             # UI・同期・マージ
└─ tests/                # 下記
```

**アダプタ**: `EarningsAdapter { id, name, requiresKey, isDummy, fetchSchedule(stocks, {apiKey, today, fetch}) → Promise<events | {events, warnings, failedCodes}> }`
を実装して `KW_ADAPTERS.register()` するだけで設定画面に出ます。失敗は `Error`（`kind`・`hint` 付き）で reject すると、理由と対処がそのまま画面に出ます。

**テスト**（モック応答のみ。実キー・実通信は使いません）
```bash
./tests/run-unit.sh                 # 単体: アダプタ/ICS/保存検証。Node.js のみ（依存なし）
node tests/e2e.js out.ics           # E2E: Playwright(headless Chromium)が必要。ICSを out.ics に保存
pip install icalendar && python3 tests/ics_crosscheck.py out.ics   # 第三者ライブラリでICSを再検証（任意）
```

**GitHub Pages**: ビルド不要ですが、このリポジトリは他の成果物と同居しているため、`apps/kessan-watch/` を公開ルートにする設定（例: GitHub Actions で公開ディレクトリを指定）が別途必要です（未設定）。

## 10. 検証状況（何を確認し、何が未確認か）

**J-Quants 仕様の出典**: 公式API仕様「決算発表予定日(/fins/earnings-date)」<https://jpx-jquants.com/ja/spec/fin-earnings-date>（2026-11-01 取得）

| 項目 | 仕様ページの記載（実装根拠） |
|---|---|
| エンドポイント | `GET https://api.jquants.com/v2/fins/earnings-date` |
| 認証 | ヘッダ `x-api-key` |
| クエリ | `code`／`date`／`scheduled_date` のいずれか1つのみ（複数指定は400）、`pagination_key`。本実装は `code`（4桁）のみ使用、最大5ページ追従 |
| 応答 | `data[]`: `PubDate, SchDate, FQName(1Q/2Q/3Q/FY), FYE(MMDD), Code(5桁), CoName, CoNameEn`、`pagination_key` |
| 履歴 | code指定は公表・変更の履歴。変更は新しい `PubDate` のレコード、未定は `SchDate=""` |

**確認済み（モック応答・自動テスト）**: 正常系／空応答／401・403・400・429・5xx・不正JSON・data無し・通信断・タイムアウト／予定変更（複数回開示→最新採用、未定化、再確定、前倒し、決算期末変更）／ページング・打ち切り／部分失敗／APIキーがURL・エラー文言・バックアップに出ないこと／ICSの構造（RFC 5545の要点＋第三者ライブラリ`icalendar`での解析）／障害時に既存表示が変わらないこと／スマホ幅で横はみ出しがないこと。

**未確認（実キーでの接続は行っていません）**:
- 実際の応答内容・エラー本文、プラン別の参照可能な公表日の範囲
- **CORS**: API への OPTIONS プリフライトが `access-control-allow-origin: *` を返すことは確認したが、実キー付き GET 応答のヘッダは未確認。不可なら中継サーバが必要
- レート制限の数値（仕様ページで確認できていない）。逐次リクエストし429で中断する独自方針
- 英字を含む新コード体系の銘柄、`FYE=0299`（2月末）の表示、`code` 4桁指定時の実挙動
- 提供データの再配布・商用利用・表示義務（J-Quants利用規約の確認が別途必要）
- Googleカレンダー等の**実アプリでの取り込み**（構造は自己検証済みだが実機未確認）
- 実機ブラウザ（Safari/Firefox/実スマホ）での確認。自動テストは headless Chromium のみ

- [ ] 決算前日・当日・通過後チェック未了のリマインド（Web Push／メール／カレンダー連携から選定）。Web Push はサーバ側の購読管理が必要

### C. 法務上の注意（投資助言に当たらない設計）
設計方針の整理であり法的結論ではありません。**公開前に金融商品取引法に詳しい弁護士へ確認すること。**
- 特定銘柄の売買推奨・目標株価・「買い／売り」判定を出さない。自己評価ラベルは利用者入力に限る
- 警戒日数などの強調表示は利用者が設定した条件に基づく表示に留める
- 有料化・外部データ再配布・AIによる要約や評価を加える場合は、助言業・代理業の登録要否、データ提供元の許諾を個別に検討
- 免責・リスク表示を全画面フッターに維持し、利用規約・プライバシーポリシーを専門家レビューのうえ正式版化（現ドラフトはそのまま商用利用しない）
- ユーザーデータをサーバ保存する構成にする場合は個人情報保護法対応、有料時は特定商取引法表記
