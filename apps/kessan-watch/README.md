# 決算ウォッチ（試作）

個人投資家向けに、ウォッチ銘柄の決算予定を管理し、決算通過後のチェックを記録する静的Webアプリ。
投資スタイルの前提は「決算を跨がず、通過確認してから判断する」。

- ビルド不要。`index.html` を開く（または GitHub Pages で `apps/kessan-watch/` を配信）だけで動作。
- データはブラウザの localStorage のみに保存。外部通信なし（ダミーアダプタ使用時）。
- **同梱の決算予定・銘柄情報はすべてダミー**（本日基準の相対日で生成した架空の値）。

## 機能（試作）
1. ウォッチ銘柄の登録・編集・削除（localStorage）
2. 決算予定のカレンダー表示／リスト表示
3. サンプルデータ同梱（半導体・AI関連14銘柄、ダミー日付）
4. データ取得のアダプタ層分離（`js/adapters.js`）。ダミー実装（サンプル14銘柄のみ日付を返す。それ以外は「予定未設定」で手動追加）と **J-Quants API V2 アダプタ**（下記）
5. 銘柄ごとの決算通過チェックリスト（実績／ガイダンス／株価反応＋自己評価・メモ・通過確認済）
6. 使い方・利用規約・プライバシーポリシー（ドラフト）
7. JSONバックアップの書出／読込
8. **ICS出力**（`js/ics.js`）。表示中の予定（リスト＝フィルタ後、カレンダー＝表示月、通過チェック＝通過済み一覧、銘柄タブ＝全件）を RFC 5545 の終日イベントとして .ics で保存。ダミー由来の予定は件名に「【ダミー】」を付ける

## 構成
```

├─ css/style.css

```

## アダプタの差し替え
`EarningsAdapter { id, name, requiresKey, isDummy, fetchSchedule(stocks, {apiKey, today}) → Promise<{code,date,period,source}[]> }`
を実装し `KW_ADAPTERS.register()` するだけで設定画面の選択肢に出る。手入力した決算日（source=`manual`）は取得結果より優先される。

## J-Quants アダプタ（実装済み・実キー未検証）
設定画面でアダプタに「J-Quants API V2」を選び、**自分のAPIキー**を入力して使う（キーはコードに含まれず、ブラウザの localStorage にのみ保存）。

**出典**: J-Quants 公式 API 仕様「決算発表予定日(/fins/earnings-date)」 <https://jpx-jquants.com/ja/spec/fin-earnings-date>（2026-11-01 に取得して実装根拠とした）

| 項目 | 実装の根拠（仕様ページの記載） |
|---|---|
| エンドポイント | `GET https://api.jquants.com/v2/fins/earnings-date` |
| 認証 | ヘッダ `x-api-key` |
| クエリ | `code`／`date`／`scheduled_date` のいずれか1つのみ（複数指定は400）、`pagination_key`。本実装は `code`（4桁）のみ使用、ページは最大5まで追従 |
| 応答 | `data[]`: `PubDate, SchDate, FQName(1Q/2Q/3Q/FY), FYE(MMDD), Code(5桁), CoName, CoNameEn`、`pagination_key` |
| 履歴の扱い | code指定は予定の公表・変更履歴。変更は新しい `PubDate` のレコードとして追加、未定は `SchDate=""` |

**本アプリでの扱い**: 決算区分（FQName＋FYE）ごとに最新 `PubDate` のレコードを採用 → 未定は除外 → 「直近の今後の予定1件」と「直近45日以内に通過した1件」を表示。日本株（4桁コード）のみ対象で、米国銘柄はスキップして警告表示。手入力の予定は取得結果より優先。

**失敗時の挙動**: 認証エラー(401/403)・400・429・5xx・通信/CORS失敗を理由付きで画面上部に表示し、表示中の予定は更新しない。「ダミーデータに切り替える」ボタンで明示的にダミーアダプタへフォールバックできる（自動では切り替えない＝ダミー日付の誤認防止）。

**未検証の範囲**（実キーでの確認は未実施。Playwrightのモック応答で、正常・401・通信失敗・フォールバック・履歴の選別ロジックのみ確認）:
- 実際の応答内容・エラー本文、プラン別の参照可能な公表日の範囲
- レート制限の数値（仕様ページで確認できていない）。逐次リクエストし429で中断する
- ブラウザからの CORS：API への OPTIONS プリフライトが `access-control-allow-origin: *` を返すことは確認したが、実キー付きGET応答の CORS ヘッダは未確認。不可なら中継サーバが必要
- 英字を含む新コード体系の銘柄、FYE が `0299`（2月末）等の表示、`code` 4桁指定時の挙動の実機確認
- 提供データの再配布・商用利用・表示義務（J-Quants利用規約の確認が別途必要）

## 商用化までの残作業

### A. 実データ連携
- [ ] J-Quants アダプタの**実キーでの検証**（上記「未検証の範囲」を解消）。レート制限の確認
- [ ] CORS が不可の場合の中継サーバ設計（APIキーの保管方法も変わる）
- [ ] データ提供元の利用規約（再配布・商用利用・表示義務・料金プラン）の確認。個人向けプランのデータを他者向けサービスで再配布できるとは限らない
- [ ] 米国銘柄の決算日ソースの選定、銘柄コード体系（東証4桁／ティッカー）の統一
- [ ] 決算日の変更・確定／未確定の区別、対象期の正規化、取得失敗時の再試行とキャッシュ
- [ ] 株価反応の自動取得（株価データのライセンス確認が前提。現在は手入力）

### B. 通知機能
- [ ] 決算前日・当日・通過後チェック未了のリマインド（Web Push／メール／カレンダー連携のいずれかを選定）
- [ ] Web Push はサーバ側の購読管理が必要。静的ホスティングだけでは完結しない
- [ ] 通知文言は事実（日付）のみとし、売買を促す表現を避ける

### C. 法務上の注意（投資助言に当たらない設計）
以下は設計方針の整理であり、法的結論ではない。**公開前に金融商品取引法に詳しい弁護士へ確認すること。**
- 特定銘柄の売買推奨・目標株価・「買い／売り」判定を出さない。自己評価ラベルは利用者入力に限る
- 警戒日数などの強調表示は利用者が設定した条件に基づく表示に留める
- 有料化・外部データ再配布・AIによる要約や評価を加える場合は、助言業・代理業の登録要否、データ提供元の許諾を個別に検討
- 免責・リスク表示を全画面フッターに維持し、利用規約・プライバシーポリシーを専門家レビューのうえ正式版化
- 個人情報・ユーザーデータをサーバ保存する構成にする場合は個人情報保護法対応、特定商取引法表記（有料時）が必要
- 現ドラフトの規約・ポリシーは試作用であり、そのまま商用利用しない
