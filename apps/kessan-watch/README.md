# 決算ウォッチ（試作）

個人投資家向けに、ウォッチ銘柄の決算予定を管理し、決算通過後のチェックを記録する静的Webアプリ。
投資スタイルの前提は「決算を跨がず、通過確認してから判断する」。

- ビルド不要。`index.html` を開く（または GitHub Pages で `apps/kessan-watch/` を配信）だけで動作。
- データはブラウザの localStorage のみに保存。外部通信なし（ダミーアダプタ使用時）。
- **同梱の決算予定・銘柄情報はすべてダミー**（本日基準の相対日で生成した架空の値）。

## 機能（試作）
1. ウォッチ銘柄の登録・編集・削除（localStorage）
2. 決算予定のカレンダー表示／リスト表示
3. サンプルデータ同梱（半導体・AI関連14銘柄、ダミー日付）
4. データ取得のアダプタ層分離（`js/adapters.js`）。ダミー実装（サンプル14銘柄のみ日付を返す。それ以外は「予定未設定」で手動追加）と J-Quants スタブ
5. 銘柄ごとの決算通過チェックリスト（実績／ガイダンス／株価反応＋自己評価・メモ・通過確認済）
6. 使い方・利用規約・プライバシーポリシー（ドラフト）
7. JSONバックアップの書出／読込

## 構成
```
apps/kessan-watch/
├─ index.html / help.html / terms.html / privacy.html
├─ css/style.css
├─ data/sample.js      # ダミーデータ
└─ js/
   ├─ adapters.js      # EarningsAdapter interface・ダミー・J-Quantsスタブ
   ├─ storage.js       # localStorage
   └─ app.js           # UI
```

## アダプタの差し替え
`EarningsAdapter { id, name, requiresKey, isDummy, fetchSchedule(stocks, {apiKey, today}) → Promise<{code,date,period,source}[]> }`
を実装し `KW_ADAPTERS.register()` するだけで設定画面の選択肢に出る。手入力した決算日（source=`manual`）は取得結果より優先される。

## 商用化までの残作業

### A. 実データ連携
- [ ] J-Quants アダプタの実装。決算発表予定日の取得に使うエンドポイント・認証方式・レート制限は**公式ドキュメントで要確認（本試作では未検証）**
- [ ] ブラウザから直接呼べるか（CORS）の確認。不可なら中継サーバが必要になり、APIキーの保管設計も変わる
- [ ] データ提供元の利用規約（再配布・商用利用・表示義務・料金プラン）の確認。個人向けプランのデータを他者向けサービスで再配布できるとは限らない
- [ ] 米国銘柄の決算日ソースの選定、銘柄コード体系（東証4桁／ティッカー）の統一
- [ ] 決算日の変更・確定／未確定の区別、対象期の正規化、取得失敗時の再試行とキャッシュ
- [ ] 株価反応の自動取得（株価データのライセンス確認が前提。現在は手入力）

### B. 通知機能
- [ ] 決算前日・当日・通過後チェック未了のリマインド（Web Push／メール／カレンダー連携のいずれかを選定）
- [ ] Web Push はサーバ側の購読管理が必要。静的ホスティングだけでは完結しない
- [ ] 通知文言は事実（日付）のみとし、売買を促す表現を避ける

### C. 法務上の注意（投資助言に当たらない設計）
以下は設計方針の整理であり、法的結論ではない。**公開前に金融商品取引法に詳しい弁護士へ確認すること。**
- 特定銘柄の売買推奨・目標株価・「買い／売り」判定を出さない。自己評価ラベルは利用者入力に限る
- 警戒日数などの強調表示は利用者が設定した条件に基づく表示に留める
- 有料化・外部データ再配布・AIによる要約や評価を加える場合は、助言業・代理業の登録要否、データ提供元の許諾を個別に検討
- 免責・リスク表示を全画面フッターに維持し、利用規約・プライバシーポリシーを専門家レビューのうえ正式版化
- 個人情報・ユーザーデータをサーバ保存する構成にする場合は個人情報保護法対応、特定商取引法表記（有料時）が必要
- 現ドラフトの規約・ポリシーは試作用であり、そのまま商用利用しない
