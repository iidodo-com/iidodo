# 業務手順書の書式（build_guide の入力）

`tools/build_guide.ps1` は、**日本語で書いた業務手順書（Markdown）** を読み込んで、画面で組み立てるための **構築手順書** を出力します。
この文書は、その入力の書き方の決まりです。記入例は [spec_example.md](spec_example.md) にあります。

- 文字コードは **UTF-8**（BOM 付きでも無しでも可）。ファイルの拡張子は `.md`。
- 書き方の決まりに合わない部分は、ツールが **警告** を出します（黙って無視はしません）。
- **サンプル（`samples/`）にない動作・設定は、構築手順書に「要確認（サンプルなし）」と表示されます。** ツールが推測で書くことはありません。

---

## 1. 全体の構成

```text
# フロー名                         ← 1行目の見出し（1つだけ）

## 目的                            ← 何のためのフローか（自由に書く）
## 事前準備                        ← 先に用意しておくもの（自由に書く）
## トリガー                        ← 何をきっかけに動くか
## 手順                            ← 処理の順番（必須）
### 1. 手順の見出し
#### 1-1. 子の手順                 ← スコープ／それぞれに適用の「中」の手順
## エラー処理                      ← 失敗したときの通知
## テスト                          ← 構築後に確認すること
```

| 章 | 必須 | 書くこと |
| --- | --- | --- |
| `# フロー名` | ○ | フローの名前（1行目） |
| `## 目的` | 推奨 | 何のためか。構築手順書の「概要」に載ります。 |
| `## 事前準備` | 任意 | Excel ファイルの場所など。箇条書きで。 |
| `## トリガー` | ○ | `- 種類: 手動` のように書く |
| `## 手順` | ○ | 処理の順番。`### 番号. 見出し` ごとに1つの箱 |
| `## エラー処理` | **推奨** | 書かないと、構築手順書に「エラー処理が未定義」の警告が出ます。 |
| `## テスト` | 任意 | あなたが決めたテストの内容。ツールが標準のテストも追加します。 |

---

## 2. 項目の書き方

**`- 項目名: 値`** の形で、1行に1項目書きます（`:` は全角の `：` でも可）。値の中に `:` があっても構いません（最初の1つで区切ります）。

```text
### 2. 一覧を読み込む
- 動作: Excel表の行を一覧表示
- ファイル: 申請一覧.xlsx
- テーブル: 申請テーブル
```

### 式を使う項目

値の中に **`{{式: 日本語の要件}}`** と書くと、式ライブラリ（`expressions/`）から、要件に合う式を探して構築手順書に載せます。

```text
- 件名: 【通知】{{式: 日本時間の今日の日付}} の処理が完了しました
```

- 要件に合う式がライブラリにないときは、「要確認（式ライブラリにありません）」と表示します（式は作りません）。
- 日本時間の日付を使う式は、構築手順書が **自動で「現在日時（日本時間）」の箱（`Compose_JST`）を追加** します。

### 前の手順の結果を使う項目

値に **`手順2の一覧`** のように書くと、その手順の結果を使う指示になります（番号は、この手順書の `### 2.` の番号）。

---

## 3. トリガー（`## トリガー`）

| 項目 | 値の例 | 状態 |
| --- | --- | --- |
| `種類` | `手動` | **対応**（サンプルあり） |
| `種類` | 定期実行／Forms／SharePoint／Outlook など | 構築手順書に「要確認（サンプルなし）」と表示（設定値は書かれます） |
| `トリガー条件` | 条件の説明 | 「要確認（サンプルなし）」と表示 |

---

## 4. 手順（`## 手順`）で使える動作

`- 動作:` に書く言葉と、書ける項目です。**別の言い方（別名）** でも通ります（表の「別名」）。

| 動作（別名） | 書ける項目 | 状態 |
| --- | --- | --- |
| **変数の初期化**（変数を初期化／変数を用意） | `変数名`、`種類`（`整数`）、`初期値` | 対応。`整数` 以外の種類は「要確認」 |
| **スコープ**（まとめる） | `名前`。中の手順は `####` で書く | 対応 |
| **Excel表の行を一覧表示**（Excel一覧取得／表の行を一覧表示） | `場所`（`OneDrive for Business`）、`ドキュメントライブラリ`、`ファイル`、`テーブル`、`ページ分け`（`オン`／`オフ`）、`しきい値`（数字）、詳細項目（`フィルタークエリ`、`並べ替え`、`上位件数`、`スキップ件数`、`列の選択`、`日付時刻の形式`） | 対応。詳細項目の内部の名前は「要確認」 |
| **それぞれに適用**（繰り返し） | `繰り返す対象`（`手順2の一覧`）、`並列度`（数字）。中の手順は `####` で書く | 対応 |
| **作成**（Compose） | `入力` | 対応 |
| **メール送信**（メールを送る） | `宛先`、`件名`、`本文`、`重要度` | 対応（Outlook の Send an email (V2)） |
| 上記以外（SharePoint・Teams・承認・Forms・条件・スイッチ など） | 自由に書ける | **サンプルがないため、構築手順書に「要確認（サンプルなし）」と表示**（動作名と、書かれた設定値はそのまま載せます） |

- 子の手順（`####`）を書けるのは、**スコープ** と **それぞれに適用** の下だけです。
- 変数の初期化は、構築手順書では **トリガーの直下** にまとめます（サンプルの置き方に合わせるため）。

---

## 5. エラー処理（`## エラー処理`）

「処理の途中で失敗したとき、メールで通知する」しくみを作ります。書くと、構築手順書は次の形になります。

```text
トリガー
Try（スコープ）… すべての手順をこの中に入れる
catch（スコープ）… Try が失敗／タイムアウトしたときだけ動く → メールを送る
```

| 項目 | 内容 |
| --- | --- |
| `通知先` | 失敗を知らせるメールの宛先 |
| `件名` | 失敗通知の件名 |
| `本文` | 失敗通知の本文 |

実行条件（「Try が失敗したときだけ動く」設定）の手順は、実際の画面で確認した操作で書かれます。

---

## 6. テスト（`## テスト`）

`### テスト1: 名前` ごとに、次の項目を書きます（どれも任意）。

| 項目 | 内容 |
| --- | --- |
| `準備` | テストデータ・事前の状態 |
| `操作` | 何をするか |
| `期待結果` | どうなればよいか |

ツールは、あなたが書いたテストに加えて、**標準のテスト**（正常に終わる／失敗時に通知される／ページ分けの確認）を追加します。

---

## 7. ツールの使い方

```powershell
# 構築手順書（Markdown）を画面に表示
powershell -NoProfile -File .\tools\build_guide.ps1 .\docs\spec_example.md

# Markdown と HTML（コピーボタン・チェック欄つき）をファイルに保存
powershell -NoProfile -File .\tools\build_guide.ps1 .\docs\spec_example.md -OutFile .\output\guide.md -Html .\output\guide.html
```
