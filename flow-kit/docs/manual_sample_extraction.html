サンプル取り出しマニュアル

Power Automate の「アクションの書き方」の見本（サンプル）を取り出して、私に渡すための手順書です。素人の方でも、上から順にやれば進められるように書いています。

0. なぜ必要か1. 全体の流れ2. 見本用フローを作る3. コードを取り出す4. 設定を変えて取る5. 伏字にする6. ファイル名を決める7. 使えるコネクタを書く8. 私に渡す9. 取り出しチェック10. 困ったとき

0. なぜ必要か

  • 次の工程（構築手順書・引継ぎ仕様書・チェック機能）は、Power Automate が内部で持っているアクションの書き方が分からないと、正しく作れません。
  • 私が記憶で書くと間違えるので、あなたの画面の実物をコピーして見せてほしいのです。
  • 見せていただくのは「アクションの設定の文字（JSON）」です。中身の個人情報や場所は、伏字にしてから渡します（第5章に、自動でほぼ処理してくれる道具があります）。
  • 全部そろわなくても構いません。◎の4種類だけでも、まず進められます。
画面の名前について
この手順の画面名は、実際にお見せいただいた英語の画面（Power Automate の編集画面にある「Parameters／Settings／Code view／About」のタブ）をもとにしています。私の想定で書いた部分は「（想定）」と書いています。違っていたら、画面を撮って送ってください。

1. 全体の流れ

手順やること目安
A見本にするアクションを用意する（見本用のフローを1本作る）20〜30分
B各アクションの「Code view」（コードの表示）をコピーする1つ2分
C設定を変えたバージョン（ページ分け・並列実行・失敗時の実行）も取る1つ5分
D伏字ツールで個人情報などを置き換える1つ1分
Eファイル名を付けて、私に渡す1つ1分

全部で約1〜1.5時間です。日を分けても構いません。

2. 見本用フローを作る（最初の1回だけ）

新しい練習用フローを1本作って、そこに「見本にしたいアクション」を並べます。本番のフローを使うより安全で、個人情報も入りません。すでに同じ種類のアクションを使っている本番フローがある場合は、そこから取っても構いません。

用意するもの

  • OneDrive に、表（テーブル）のある練習用の Excel ファイル（データは適当な数行でよい）。
  • 練習用の自分宛のメールアドレス（失敗通知の送り先に使う）。

作るフローの形（◎の4種類が全部入ります）

完成図

図の番号（②〜⑦）は、下の手順の番号と同じです。図は第2章の手順どおりに作った最終の形です（Apply to each は Try の中に置く形で描いています。外に置いても構いません）。

  1. Create →「Instant cloud flow」→ 名前を 見本づくり にして、Manually trigger a flow を選んで Create。
  2. ＋ →「Scope」を追加し、名前を Try にします（箱の「…」→「Rename」）。
    ※ 検索欄に Scope と入れると出ます（コントロールの仲間）。
  3. Try の中の ＋ で、Excel Online (Business) の List rows present in a table を追加し、練習用の Excel ファイルとテーブルを選びます。
  4. その下に Apply to each を追加します（Try の中でも外でも構いません）。
    「Select an output from previous steps」の欄をクリックし、欄の右端の上のアイコン（稲妻＝動的なコンテンツ）を押して、List rows present in a table の下の value を選びます。
    見つからないときは、右端の下のアイコン（fx）で式の欄を開き、body('List_rows_present_in_a_table')?['value'] を貼って Add。
    続いて、箱の中の ＋ で Compose を1つ追加し、入力は何でもよい（例：test）。
  5. Try の外の下に、もう1つ Scope を追加し、名前を Catch にします。
  6. Catch の中に Outlook の Send an email (V2)（メールの送信）を追加し、宛先に自分、件名と本文に「失敗しました」などを入れます。
  7. Catch を、「Try が失敗したときだけ動く」設定にします（第4章の「実行条件の構成」）。
  8. 保存します。実行しなくても、見本は取れます（実行すると、失敗時のメールを試すこともできます）。

手順4の入力場所（図）

うまく作れないとき
どの手順でも、分からなければ画面を撮って送ってください。一緒に進めます。作れたアクションだけでも、先に取り出して渡してもらえれば、そこから進められます。

3. 「Code view」からコードを取り出す（基本）

1つのアクションの設定を、文字としてコピーします。すべてのアクションで同じ手順です。

  1. フローを編集画面で開きます。
  2. 取り出したいアクションの箱をクリックします。左側にパネルが開き、上に Parameters／Settings／Code view／About のタブが並んでいます（お見せいただいた画面で確認済み）。
  3. Code view（コードの表示）のタブをクリックします。
    ※ 古い画面では、箱の「…」→「Peek code」（コードのプレビュー）という名前のことがあります。
  4. 表示された文字（{ ... } で始まるもの）を、全部選んでコピーします（文字の中をクリック → Ctrl＋A → Ctrl＋C）。
  5. メモ帳を開き、貼り付けます（Ctrl＋V）。
  6. 次の第5章の「伏字ツール」に貼り付けて、個人情報などを置き換えます。
最初の1つで確認
最初に Compose（いちばん簡単なもの）で試して、表示された内容を私に貼ってください。取り出し方がこれで合っているか、私が確認します。その後で、他のアクションに進んでください。
注意
  • 「Parameters」タブの画面そのもの（スクリーンショット）ではなく、Code view の文字が必要です。
  • コピーした文字を、手で直したり、並べ替えたりしないでください。画面に出たままの形が大事です。
  • スコープや Apply to each は、中のアクションをまとめて含む形で取れる場合があります。そのまま1つのファイルにしてください。

4. 設定を変えたバージョンも取る

同じアクションでも、設定を変えると書き方が変わります。変える前と後の2つを取ってください（ファイル名の付け方は第6章）。

取りたいものどこを変えるか（想定）取る回数
Excel：ページ分け（ページネーション）List rows present in a table の箱 →「Settings」タブ → Pagination（ページネーション）をオン／オフ。オンのときは「しきい値（Threshold）」に数字（例：5000）オフ・オンの2回
Apply to each：並列実行（コンカレンシー）Apply to each の箱 →「Settings」タブ → Concurrency control をオン／オフ。オンのときは並列度（例：4）オフ・オンの2回
失敗時にだけ動く（実行条件の構成）Catch の箱（またはその中のメール送信）→ Settings タブの中の Run after（実行条件の構成）。「is successful」を外して、「has failed」「has timed out」にチェック変更後の1回（必要なら変更前も）
Excel：日付の形式List rows present in a table の「Parameters」タブの Advanced parameters の中の DateTime Format（日付/時刻の形式。画面で確認済み）。ドロップダウンから選ぶ（選択肢の中の「ISO 8601」を選ぶ想定）選んだ状態の1回
トリガー条件トリガーの箱 →「Settings」タブ → Trigger conditions（トリガー条件）に、条件の式を1つ入れる（例：@equals(1,1)）設定後の1回

項目名は私の想定で、実際の画面と違うかもしれません。見つからないときは、その箱の「Settings」タブと「Parameters」タブの画面を、撮って送ってください。

「Try が失敗したときだけ」の設定（実行条件の構成）のやり方（想定）

  1. Catch のスコープの箱をクリックします。
  2. 左のパネルの Settings タブを開き、Run after（実行条件の構成）を探します。
  3. 前の箱の名前（Try）が表示されます。その下の「is successful」のチェックを外し、「has failed」と「has timed out」にチェックを付けます。
  4. 保存してから、Catch の箱の Code view を取り出します（runAfter の中身が変わります）。

5. 伏字にする（伏字ツール）

大事なこと
  • このツールはブラウザの中だけで動き、文字をどこにも送信しません（インターネットに接続していなくても動きます）。
  • ただし自動で見つけられるものには限りがあります。置き換え後は、必ず自分の目でも確認してください（氏名・案件名・課の名前など）。
  • 置き換えるのは中身（値）だけです。項目名や構造は変えません。
  1. 下の左の枠に、第3章でコピーした Code view の文字を貼り付けます。
  2. 「伏字にする」を押します。
  3. 右の枠に、置き換え後の文字が出ます。下の「要確認」の一覧を見て、残っている個人情報がないか確認します。
  4. 問題なければ、「コピー」か「ファイルに保存」を押します。

6. ファイル名を決める（ファイル名メーカー）

ファイル名は、コネクタ略称__アクション内容__バリエーション.json の形にします。半角英数字と _ だけ（日本語は使わない）。下の道具で作れます。管理表（_manifest.csv）の1行も一緒にできます。

7. 使えるコネクタを書く（connectors.txt メーカー）

「使えるコネクタ」の一覧を、次の道具で作ります。使うものにチェックを入れ、区分（Standard／Premium／組み込み）を、画面のコネクタの表示を見て選んでください。分からなければ「不明」で構いません。

Premium のコネクタは、この一覧に入れません（使えない前提のため）。「Premium」を選んだ行は、出力から除きます。
使うコネクタ名英語名区分備考

できた文章は、メモ帳に貼り付けて、connectors.txt（UTF-8）として保存するか、そのまま私に貼って送ってください。

8. 私に渡す

  1. 伏字にした文字（第5章の「置き換え後」）を、このチャット画面に貼り付けて送ってください。1回の送信に、1〜3ファイル分ずつが目安です。長いときは、分けて送ってください。
  2. 貼り付けるときは、ファイル名（第6章）を最初の行に書いてください。例：
    【excel__list_rows_in_table__pagination_on.json】
  3. 管理表の行（第6章で作ったもの）も、いっしょに貼ってください。
  4. 私が受け取ったら、flow-kit/samples/ に保存して、Git に反映します。あなたが Git やファイル操作をする必要はありません。
  5. connectors.txt の内容（第7章）も、貼り付けて送ってください。
まずCompose の1つだけ送ってください。取り出し方が合っているかを確認して、続けて進める順番を案内します。

10. 困ったとき

「Code view」のタブが見つからない

箱をクリックしたあとの、左のパネルの上に、Parameters・Settings・Code view・About のタブがあるはずです。見つからないときは、箱の「…」メニューに「Peek code」（コードのプレビュー）があるかも探してください。それでも見つからなければ、画面を撮って送ってください。

表示された文字が長すぎて、全部コピーできない

文字の中をクリックして Ctrl＋A（全部選ぶ）→ Ctrl＋C（コピー）を押してください。マウスで選ぶより確実です。

伏字ツールで「JSONとして読み取れません」と出た

コピーの途中が切れているか、最初や最後の { } が抜けている可能性があります。もう一度、Ctrl＋A でコピーし直してください。

何を伏字にすればいいか分からない

迷ったときは、置き換えてください。構造（項目名）は変わらないので、中身を置き換えても問題ありません。置き換えて困ることは、ほとんどありません。

個人名や案件名が入っていた

手で 担当者名、案件名 などに置き換えてください。アクションの名前に個人名が入っているときは、名前を参照している式の中も同じ名前に直してください（分からなければ、そのまま送らず、相談してください）。

見本用フローを作る時間がない

すでに動いている本番フローから、同じ種類のアクションを取り出しても構いません。その場合も、必ず伏字にしてください。本番の個人情報が多いときは、見本用フローの方が安全です。
