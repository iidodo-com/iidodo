# 構築手順書：窓口アンケートの回収

> この手順書は `tools/build_guide.ps1` が、業務手順書（`spec_unsupported.md`）から作成しました。
> **画面でフローを人が組み立てる**ための手順です（JSONを取り込む方式ではありません）。

## 作成時の警告

- ⚠ 「## エラー処理」が書かれていません。失敗しても誰にも通知されないフローになります（構築手順書にエラー処理は含めません）。

## 0. この手順書の見方

- ［画面で確認済み］：実際の画面に表示された名前を、確認した項目です。
- ［サンプルで確認済み］：`samples/` のサンプルJSONにある書き方です。
- ［想定］：画面の名前を、まだ実際の画面で確認していない項目です（画面の表示と違うときは、画面の名前を優先してください）。
- ［要確認（サンプルなし）］：サンプルがなく、書き方を断定できない項目です。最後の「要確認の一覧」にまとめています。
- 日本語の画面表示の名前は、サンプルがないため **すべて「要確認（サンプルなし）」** です。画面が日本語表示のときは、英語名の意味から探し、見つけた名前を教えてください。

## 1. 概要

- Forms の回答を SharePoint のリストに保存する。

### 使うコネクタ

- ［要確認（サンプルなし）］ 手順 1「回答を取得する」の動作（Forms 応答の詳細を取得）
- ［要確認（サンプルなし）］ 手順 2「リストに保存する」の動作（SharePoint 項目の作成）

### 完成後のフローの形

```text
[トリガー] Forms 新しい応答（要確認）
[Forms 応答の詳細を取得]  ← 要確認（サンプルなし）
[SharePoint 項目の作成]  ← 要確認（サンプルなし）
```

## 6. 構築後のテスト

### 6-1. 保存と実行のしかた

1. 右上の「Save」（保存）を押す。**赤い印（Invalid parameters）の箱が残っていると保存できません。** 赤い箱を開いて、必須の項目（赤い * の項目）を入力する。
2. 「Test」→「Manually」→「Run flow」→「Done」で実行する。 ［想定］
3. 実行結果の画面で、各箱の緑（成功）／赤（失敗）／灰色（実行されない）を確認し、箱をクリックして入力と出力を見る。

### 6-3. 標準のテスト（このツールが追加）

#### 標準テスト A：最後まで正常に動く

- [ ] 準備：業務手順書の手順どおりに、少ない件数のテストデータを用意する
- [ ] 操作：フローを手動で実行する
- [ ] 期待結果：すべての箱が緑になる。

## 7. 要確認の一覧（サンプルなし）

日本語の画面表示の名前は、すべての箱で **要確認（サンプルなし）** です（英語表示は、画面で確認できたものと想定のものを区別して書いています）。

| 場所 | 要確認の内容 |
| --- | --- |
| 式 | 要件「存在しない要件ほげほげ」に合う式が式ライブラリにありません |
| トリガー | 「Forms 新しい応答」のトリガーのサンプルがありません |
| トリガー | トリガー条件の設定のしかた・書き方のサンプルがありません |
| 手順 1 | 動作「Forms 応答の詳細を取得」のサンプルがありません（箱の名前・項目名・JSON） |

これらは、該当する箱のサンプル（`docs/sample_checklist.md` の手順で取り出したコードのプレビュー）を `samples/` に追加すると、次の版から確認済みの書き方で出力できます。
