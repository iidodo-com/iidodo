# 構築手順書：申請一覧の取込と完了通知

> この手順書は `tools/build_guide.ps1` が、業務手順書（`spec_example.md`）から作成しました。
> **画面でフローを人が組み立てる**ための手順です（JSONを取り込む方式ではありません）。

## 0. この手順書の見方

- ［画面で確認済み］：実際の画面に表示された名前を、確認した項目です。
- ［サンプルで確認済み］：`samples/` のサンプルJSONにある書き方です。
- ［想定］：画面の名前を、まだ実際の画面で確認していない項目です（画面の表示と違うときは、画面の名前を優先してください）。
- ［要確認（サンプルなし）］：サンプルがなく、書き方を断定できない項目です。最後の「要確認の一覧」にまとめています。
- 日本語の画面表示の名前は、サンプルがないため **すべて「要確認（サンプルなし）」** です。画面が日本語表示のときは、英語名の意味から探し、見つけた名前を教えてください。

## 1. 概要

- OneDrive の「申請一覧」（Excel）の行を1件ずつ確認する。
- 処理が終わったら、担当者にメールで知らせる。
- 途中で失敗したときも、担当者にメールで知らせる。

### 使うコネクタ

- 組み込み（変数） ／ Initialize variable（日本語表示名：［要確認（サンプルなし）］）
- Excel Online (Business) ／ List rows present in a table（日本語表示名：［要確認（サンプルなし）］）
- 組み込み（コントロール） ／ Apply to each（日本語表示名：［要確認（サンプルなし）］）
- 組み込み（データ操作） ／ Compose（日本語表示名：［要確認（サンプルなし）］）
- Office 365 Outlook ／ Send an email (V2)（日本語表示名：［要確認（サンプルなし）］）
- 組み込み（コントロール） ／ Scope（日本語表示名：［要確認（サンプルなし）］）

### 完成後のフローの形

```text
[トリガー] Manually trigger a flow
[Initialize variable]  変数 counter
[Scope] Try
   [List rows present in a table]
   [Apply to each]
      [Compose]
   [Send an email (V2)]
[Scope] catch
   [Send an email (V2)]
```

## 5. エラー処理（失敗したときにメールで知らせる）

仕組み：すべての手順を `Try`（スコープ）に入れ、`catch`（スコープ）を **Try が失敗した／タイムアウトしたときだけ** 動かして、メールを送ります。

### 5-1. catch（スコープ）を作る

1. **Try の下**の「＋」→「Add an action」→ `Scope` を追加 ［想定］
2. 名前を `catch` に変える（「…」→「Rename」） ［想定］

### 5-2. catch の中に、失敗通知のメールを作る

1. `catch` の中の「＋」→ `Send an email (V2)`（Outlook） ［画面で確認済み］（`Send an email (V2)` の名前は画面で確認）

| 画面の項目（英語表示） | 設定する値 | JSON での書き方（サンプル） |
| --- | --- | --- |
| To ［想定］ | tantou@example.com | emailMessage/To |
| Subject ［想定］ | 【失敗】申請一覧の確認で失敗しました | emailMessage/Subject |
| Body ［想定］ | フローの実行履歴を確認してください。 | emailMessage/Body（HTML で保存される） |

### 5-3. catch を「Try が失敗したときだけ動く」設定にする（実行条件の構成）

1. `catch` の箱をクリックし、左のパネルの「**Settings**」タブを開く ［画面で確認済み］
2. 「**Run after**」の下に、いま動かすきっかけの箱（直前の箱）が出る ［画面で確認済み］
3. 「**＋ Select actions**」を押し、一覧から **`Try`** にチェックを入れる ［画面で確認済み］
4. `Try` の行で、「**Is successful**」の**チェックを外し**、「**Has timed out**」と「**Has failed**」に**チェック**を付ける ［画面で確認済み］（「Is skipped」は外したまま）
5. **直前の箱（例：Apply to each や別の箱）の行が残っていたら、右端のゴミ箱で削除する。** 残すと、その箱が成功し、かつ Try が失敗しないと動かない設定になり、catch が動きません ［画面で確認済み］
6. 保存する

**Code view で確認するポイント**（`catch` の箱）：`"type": "Scope"`、`"runAfter": { "Try": ["TimedOut", "Failed"] }` ［サンプルで確認済み］（`samples/actions/control__scope__run_after_failed.json`）

> 正常に終わったときは、catch の箱は灰色（実行されない）のままになります（実行結果の画面で確認）。

## 6. 構築後のテスト

### 6-1. 保存と実行のしかた

1. 右上の「Save」（保存）を押す。**赤い印（Invalid parameters）の箱が残っていると保存できません。** 赤い箱を開いて、必須の項目（赤い * の項目）を入力する。
2. 「Test」→「Manually」→「Run flow」→「Done」で実行する。 ［想定］
3. 実行結果の画面で、各箱の緑（成功）／赤（失敗）／灰色（実行されない）を確認し、箱をクリックして入力と出力を見る。

### 6-2. 業務手順書のテスト

#### テスト 1：件数が少ない表で最後まで動く

- [ ] 準備（テストデータ）：申請テーブルに3行のテストデータを入れる（例: A001〜A003）
- [ ] 操作：フローを手動で実行する
- [ ] 期待結果：すべての箱が緑になり、完了通知のメールが1通届く

#### テスト 2：表が見つからないときに失敗通知が届く

- [ ] 準備（テストデータ）：申請一覧.xlsx の名前を一時的に変える
- [ ] 操作：フローを手動で実行する
- [ ] 期待結果：Try が赤になり、catch が動いて失敗通知のメールが届く

### 6-3. 標準のテスト（このツールが追加）

#### 標準テスト A：最後まで正常に動く

- [ ] 準備：業務手順書の手順どおりに、少ない件数のテストデータを用意する
- [ ] 操作：フローを手動で実行する
- [ ] 期待結果：すべての箱が緑になる。`catch` は灰色（実行されない）のまま。失敗通知のメールは届かない。

#### 標準テスト B：わざと失敗させて、失敗通知が届くことを確認する

- [ ] 準備：**練習用のデータ**で行う（本番のデータでは行わない）。Try の中の箱が失敗する状態にする（例：Excel のファイル名を一時的に変える）
- [ ] 操作：フローを手動で実行する
- [ ] 期待結果：`Try` が赤になり、`catch` が緑で動いて、失敗通知のメールが届く（宛先・件名・本文が第5章の設定どおり）
- [ ] 後片付け：変えた名前などを元に戻す

#### 標準テスト C：行数の多い表で、全件が取得できる

- [ ] 準備：Excel の表に、多めの行数のテストデータを入れる（ページ分けのしきい値より多い行数）
- [ ] 操作：フローを手動で実行する
- [ ] 期待結果：Excel の一覧取得の出力の件数が、表の行数と一致する（件数は式ライブラリ 08「配列の件数」の式で数えられる）
- 注意：ページ分けの設定がない場合、既定の上限で打ち切られる恐れがあります。既定の上限の件数は、サンプルがなく**要確認**です。
